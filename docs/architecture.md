## 3. 목표 구조

```
브라우저
  ├─ 새 UI (Vite 빌드, Preact 컴포넌트, 디자인 시스템 토큰)  ← 페이지 단위로 점진 교체
  └─ 기존 UI (public/)                                      ← 교체 완료 시 제거
        │  /api/v2/* (화면 단위 집계 API, 캐시·속도 제한·출처/기준시각 포함)
        ▼
Express
  ├─ src/nexon/       넥슨 호출 계층: 캐시(TTL+LRU), 동시 요청 병합, 동시성 제한, 429/5xx 백오프  [구현됨]
  ├─ src/game-data/   게임 규칙 데이터(월드·직업·확률표·강화 비용 등) + 출처·적용 패치·확인일 메타데이터
  ├─ src/domain/      계산 로직(스탯 기여도, 잠재 상위 %, HEXA 비용, 전투력 추정 등) — 순수 함수, 단위 테스트
  ├─ src/transform/   넥슨 응답 → 화면용 모델 변환(필드 삭제·추가에 대응하는 단일 지점)
  ├─ src/storage/     MongoDB 모델: 성장 스냅샷(압축), 최신 원본 1건, 사용자·즐겨찾기, 관리 로그
  ├─ src/jobs/        정기 작업: 랭킹 일일 수집, 스키마 변경 감지, 오래된 데이터 정리, 백업 확인
  └─ src/admin/       관리자 API(게임 상수·공지·수집 상태·오류 제보)
```

### 3.1 넥슨 호출 계층 (구현 완료, 테스트 완료)

- `src/nexon/client.js`: 모든 넥슨 호출이 이곳을 지난다.
- 캐시 TTL: `/id`·`/guild/id` 6시간, 오늘 랭킹 5분, 지난 날짜 랭킹 6시간, 캐릭터·유니온·길드 상세 2분(넥슨 반영 지연이 평균 10~15분이므로 2분 캐시는 체감 신선도에 영향이 작다).
- 클라이언트 오류(4xx, 429 제외)는 60초 실패 캐시 → 없는 캐릭터 반복 조회 차단.
- 같은 요청 동시 발생 시 넥슨 1회만 호출. 동시 호출 상한 8.
- 429·5xx·네트워크 오류는 지수 백오프(+지터) 후 최대 2회 재시도, `Retry-After` 우선.
- 사용량은 10분마다 서버 로그에 `[Nexon] {...}` 한 줄로 남긴다(일일 한도 감시용).
- 썸네일 전용 `/api/maplestorym/character/image`는 이미지 주소만 12시간 캐시.

### 3.2 데이터 저장 (목표)

넥슨 약관(API 문서 고지)상 "크롤링한 데이터는 30일 이내 갱신" 의무와 해지 시 삭제 의무가 있다. 저장 구조는 이를 전제로 설계한다.

| 컬렉션 | 내용 | 보관 |
|---|---|---|
| `character_snapshots` | 캐릭터·날짜별 요약(레벨, 경험치, 경험치율, 주요 스탯, 전투력 관련 값, 장비 요약 해시) 수백 바이트 | 성장 기록용. 보관 기간은 넥슨 문의 결과에 따라 결정(운영자 결정 사항) |
| `character_latest` | 캐릭터별 최신 원본 1건(프리셋 복원·챗봇용) | 30일 이내 갱신, 오래되면 표시 시 "N일 전 데이터"로 명시 |
| `requestlogs` (기존) | 넥슨 원본 로그 | 운영자 결정 전까지 보존. 신규 저장은 요약 스냅샷으로 전환 |
| `users`, `favorites`, `user_characters` | 계정·즐겨찾기·소유 인증 | 탈퇴 시 삭제 |
| `admin_audit` | 관리자 작업 이력 | 1년 |

### 3.3 API 설계 (목표)

- 원본 프록시 23개는 새 UI 전환 후 제거한다(약관 제5조 ⑤ "제3자 재제공" 소지, 할당량 남용 위험). 전환 기간에는 속도 제한을 건다.
- `/api/v2/characters/:world/:name` → 화면용 모델 + `meta.source`(공식 API / 자체 계산 / 사용자 입력), `meta.asOf`(넥슨 데이터 기준 시각), `meta.fetchedAt`.
- `/api/v2/rankings/:type?date&world&page` → 서버에서 표시용 필드만 + 기준일 자동 보정(빈 날짜는 최근 집계일).
- ocid는 서버 내부에서만 쓰고 응답·URL에 싣지 않는다(넥슨 AI 가이드 권고).

### 3.4 프런트엔드 (목표)

- **Vite + Preact + JSX**, JS + JSDoc. 빌드 산출물은 `dist/`(파일 해시로 캐시 무효화 → 수동 `?v=` 제거).
- Express는 `dist/`의 새 페이지를 먼저 찾고, 없으면 기존 `public/`으로 대체 → 페이지 단위로 전환.
- 캐릭터 상세처럼 무거운 화면은 탭 단위 코드 분할. 차트는 직접 만든 SVG 컴포넌트(데이터 양이 많아지면 uPlot 검토).
- 공유 미리보기(카카오·디스코드)를 위해 서버가 캐릭터 페이지 HTML에 `og:*` 메타를 주입.
- 선택 근거: 계산기·시뮬레이터·비교 같은 상호작용이 많아져 컴포넌트 단위 상태 관리가 필요하고, Preact는 React 문법 그대로 3KB대라 유지보수자가 구하기 쉽다. 서버를 SSR 프레임워크(Next.js 등)로 바꾸는 것은 운영 구조(체크아웃 = 운영) 변경 폭이 커서 보류.

### 3.5 배포 (목표)

현재는 "체크아웃 = 운영"이라 `public/` 저장 즉시 반영된다. 개편 후에는:

1. worktree에서 개발 → `npm test` + 브라우저 점검.
2. `main`에 병합 → 운영 체크아웃에서 `npm ci && npm run build`.
3. 같은 서버의 다른 포트로 새 버전을 띄워 스모크 테스트(`scripts/dev/browser.js`).
4. 운영자 승인 후 `pm2 reload maplem`(무중단) → 실패 시 이전 커밋으로 되돌리고 `pm2 reload`.
5. Cloudflare 캐시 퍼지(해시 파일명을 쓰면 HTML만).
