# 경쟁 사이트 기능 인벤토리: maplemworlds.kr

- 조사일: 2026-10-28 (KST 14:48~15:26 관찰. 수치는 모두 이 시점 값)
- 대상: maplemworlds.kr (메이플스토리M 팬사이트, 푸터 표기 "Data by NEXON Open API", 화면 하단 빌드 시각 2026-10-28 10:55 KST)
- 목적: maplem.co.kr(메이플M 플러스) 전면 개편을 앞두고 경쟁 기능과 사용 흐름을 파악한다. 이 문서는 기능과 흐름을 우리 말로 추상화해 정리했고, 상대 사이트의 코드·문구·그래픽·레이아웃은 옮기지 않았다.

## 0. 조사 방법과 범위

- 도구: Headless Chromium(Playwright). 데스크톱 1440x900, 모바일 390x844(터치·모바일 UA)로 렌더링한 뒤 본문 텍스트, 링크·버튼 목록, `title` 툴팁, 스크린샷으로 확인했다.
- 분량: 페이지 이동과 페이지 안의 탭·필터 조작을 합쳐 92회 기록(전체 페이지 로드는 약 80회), 고유 경로 45개. 이동 사이에는 1.5초 이상 쉬었다.
- 흔적 차단: 브라우저 단에서 maplemworlds.kr로 나가는 GET 이외 요청(POST 등)을 모두 막았다. 조사 중 막힌 요청은 사이트 자체 로그 전송 44건(행동 로그 `/api/logs/action` 43건, 캐릭터 비교 로그 `/api/logs/compare` 1건)뿐이었다. 로그인·회원가입·글쓰기·제보·랭킹 등록·"기록 남기기"·갱신 버튼은 누르지 않았다.
- 표본: 랭킹 상위 캐릭터 4명(인증 3명, 미인증 1명)의 상세 페이지 전 탭, 길드 1곳(랭킹 상위) 상세, 캐릭터 비교 1건, 장비 추적 검색 1건. 개인 식별을 줄이려고 이 문서에는 캐릭터명을 적지 않았다.
- 확인 상태 기준
  - 확인 완료: 화면을 열고 주요 조작(탭·필터·입력 변경)을 직접 해 결과 변화까지 봤다.
  - 일부 확인: 화면과 안내 문구는 봤지만 핵심 동작(저장·제출·갱신·로그인 후 기능)을 실행하지 않았거나, 계산식이 공개되지 않았다.
  - 확인 불가: 로그인이 필요해 화면을 볼 수 없었다. 공개된 안내 문구로만 추정했다.
- 정정 1건: 요청서의 메뉴 목록에 있던 "실시간 상가"는 별도 기능이 아니었다. 헤더의 **실시간 인기 검색 티커**가 순위권 캐릭터 이름을 돌아가며 보여 주는데, 마침 '상가'라는 이름의 캐릭터가 표시된 순간의 라벨이었다. 같은 버튼이 시점에 따라 다른 캐릭터명으로 바뀌는 것을 여러 번 확인했고, 티커를 펼친 목록 1위도 같은 이름의 캐릭터였다.
- 용어(상대 사이트 표기 기준): 최댐 = 최대 대미지, 에디 = 에디셔널 잠재, 아드 = 아이템 드롭률, 메획 = 메소 획득량, 템환산 = 장비 옵션을 점수 하나로 환산한 자체 지표, 문장 = 무기류에 붙는 문장(무자비·압도 등). "템환산(포함/미포함)"의 포함 대상은 문장이다(아이템 툴팁 표기로 확인).

### 우리에게 가장 가치 있는 기능 Top 10

1. F27 데이터 갱신(마지막 갱신 시각·갱신 버튼): 데이터 신뢰도와 직결되는데 우리 쪽에는 없다. 쿨다운만 설계하면 된다.
2. F03 즐겨찾기·최근 조회: 로그인 없이 재방문 동선을 줄인다. 브라우저 저장만으로 구현할 수 있다.
3. F14 스탯 효율: "무엇을 올려야 하나"라는 질문에 바로 답한다. 계산 근거를 공개하면 경쟁사보다 신뢰받을 수 있다.
4. F26 장비 교체 체험: 경쟁사가 10/24에 낸 최신 핵심 기능이다. 강화·교체 판단을 사이트 안에서 끝내게 한다.
5. F13+F28 템환산 점수와 자체 스펙 랭킹: 랭킹·비교·장비 추적이 모두 이 점수 하나를 공유한다.
6. F35 캐릭터 비교: 이미 가진 상세 데이터를 재사용하므로 빨리 만들 수 있고, 공유 유입도 기대된다.
7. F20 변경 이력 + F19 성장 기록 확장: ocid 기준 스냅샷을 우리도 이미 쌓고 있어 추가 비용이 적다.
8. F48 헥사 강화 기간 계산기 + F49 HEXA 스탯 시뮬레이터: 지금 성장 메타의 핵심 재화를 다룬다. 로직도 단순하다.
9. F18 보스 입장 전투력 표 + F17 보스 세팅: 캐릭터 데이터와 바로 이어지는 실용 정보다.
10. F55 공지·패치노트 모아보기 + F08 웹 푸시: 패치 주기에 맞춰 사용자를 다시 부르는 장치다.

## 2. 기능별 상세

공식 API 표기는 우리 서버가 이미 쓰는 메이플스토리M Open API 엔드포인트 이름을 따른다(`id`, `character/basic`, `stat`, `hyper-stat`, `guild`, `item-equipment`, `cashitem-equipment`, `symbol`, `set-effect`, `jewel`, `android-equipment`, `pet-equipment`, `skill-equipment`, `link-skill`, `vmatrix`, `hexamatrix-skill`, `hexamatrix-stat`, `beauty-equipment`, `user/union`, `user/union-raider`, `guild/id`, `guild/basic`, `ranking/*`). 이 목록에 없는 데이터는 "목록 밖"으로 표시하고 대안을 적었다. 최신 API 목록 조사 결과에 따라 일부는 바뀔 수 있다.

### 2-1. 검색·공통·개인화

#### F01. 통합 검색(캐릭터/길드)
- 접근 경로: 모든 페이지 헤더. 결과는 `/character/{월드}-{캐릭터명}`, `/guild/{월드}-{길드명}`.
- 기능 설명: 월드 선택, 이름 입력, 캐릭터/길드 모드 전환을 검색창 하나로 처리한다. 입력창에 포커스하면 최근 조회 캐릭터 목록과 일괄 갱신 버튼이 펼쳐진다. Enter를 누르면 캐릭터 상세로 바로 이동하고, 중간 결과 페이지는 없다. 입력창 안내문에 '/' 단축키가 표기돼 있다.
- 입력 데이터: 월드(7개: 스카니아·루나·크로아·엘리시움·제니스·유니온·아케인), 이름, 검색 모드.
- 결과 데이터: 해당 상세 페이지로 이동. 마지막으로 고른 월드를 브라우저에 기억한다.
- 화면 구성 핵심 요소: 헤더 중앙의 한 줄 검색 바(월드 드롭다운, 입력, 모드 토글). 모바일에서는 헤더 둘째 줄로 내려간다.
- 필요한 공식 API(추정): `id`(이름 → ocid), `character/basic`. 길드는 `guild/id`, `guild/basic`.
- 추가 데이터·계산식: 최근 조회 목록(브라우저 저장). URL 규칙은 `월드-이름` 한 덩어리다.
- 구현 난이도: 하
- 우리 사이트 유사 기능: 캐릭터 검색(`/character/:월드/:이름`)은 있다. 길드는 별도 경로(`/guild/:월드/:이름`)이고 헤더 통합 토글과 최근 조회 드롭다운은 없다(확인 필요).
- 우선순위 제안: P0. 모든 기능의 입구라 동선 품질이 체감 품질을 좌우한다.
- 확인 상태: 확인 완료. 캐릭터 검색 Enter 이동과 최근 조회 드롭다운까지 확인했다. 길드 모드는 전환과 입력까지만 해 봤고(입력 중 자동완성 결과는 없었음), '/' 단축키는 표기만 봤다.

#### F02. 실시간 인기 검색 티커
- 접근 경로: 헤더 오른쪽(모바일은 헤더 첫 줄).
- 기능 설명: 최근 많이 조회된 캐릭터 이름을 한 줄로 돌려 보여 주고, 펼치면 상위 10명(아바타·월드·직업)이 나온다. 항목을 누르면 상세로 이동한다. 요청서의 "실시간 상가"는 이 티커의 순간 라벨이었다(0장 참고).
- 입력 데이터: 없음(사이트 조회 로그).
- 결과 데이터: 순위, 캐릭터명, 월드, 직업, 아바타.
- 화면 구성 핵심 요소: 작은 드롭다운 버튼, 펼침 목록(번호와 아바타).
- 필요한 공식 API(추정): 목록 밖(자체 조회 로그 집계). 표시용 아바타·직업은 `character/basic`.
- 추가 데이터·계산식: 집계 기간과 산정 방식은 공개되지 않았다.
- 구현 난이도: 중(집계·캐시·어뷰징 방지)
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2. 커뮤니티 활기를 보여 주지만 핵심 가치는 아니다.
- 확인 상태: 확인 완료. 드롭다운 목록과, 라벨이 시점마다 바뀌는 것을 관찰했다.

#### F03. 즐겨찾기·최근 조회(비로그인)
- 접근 경로: 캐릭터 상세의 별 버튼, 홈의 즐겨찾기 카드, 검색창 드롭다운.
- 기능 설명: 로그인 없이 브라우저 저장소에 즐겨찾기와 최근 조회 캐릭터를 쌓는다. 홈 카드와 검색 드롭다운에서 다시 쓴다. 추가하면 짧은 알림이 뜬다.
- 입력 데이터: 별 버튼 클릭.
- 결과 데이터: 저장 항목은 월드, 이름, 직업, 레벨, 아바타 이미지 주소.
- 화면 구성 핵심 요소: 상세 상단 아이콘 버튼, 홈 카드(비어 있으면 사용법 안내).
- 필요한 공식 API(추정): 없음(저장 시점의 `character/basic` 값을 재사용).
- 추가 데이터·계산식: 없음
- 구현 난이도: 하
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P0. 비용 대비 재방문 효과가 가장 크다. 나중에 로그인이 생기면 동기화로 확장할 수 있다.
- 확인 상태: 확인 완료. 별 버튼을 누른 뒤 저장소에 즐겨찾기·최근 조회 키가 생기는 것까지 확인했다.

#### F04. 로그인·회원가입
- 접근 경로: `/login`, `/login?mode=register`. 비로그인으로 `/account`에 가면 `/login`으로 보낸다.
- 기능 설명: 이메일·비밀번호 또는 카카오 계정으로 가입하고 로그인한다. 로그인 유지(30일)와 비밀번호 찾기가 있다. 가입 화면은 계정 복구용으로 실제 받을 수 있는 이메일을 쓰라고 안내한다. 업데이트 내역상 기존 계정과 카카오 계정 연동도 지원한다.
- 입력 데이터: 이메일, 비밀번호(8자 이상) 또는 카카오 OAuth.
- 결과 데이터: 세션(로그인 후 화면은 확인 불가).
- 화면 구성 핵심 요소: 로그인/가입 탭, 소셜 로그인 버튼, 유지 체크박스.
- 필요한 공식 API(추정): 해당 없음(자체 회원 시스템과 카카오 OAuth).
- 추가 데이터·계산식: 없음
- 구현 난이도: 상(보안, 개인정보 처리방침, 계정 복구)
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2. F05의 기반이지만 개편 1차 범위에서는 로그인 없는 개인화(F03)가 먼저다.
- 확인 상태: 일부 확인. 화면만 봤고 입력·제출은 하지 않았다.

#### F05. 내 캐릭터(소유 인증·부캐 연동·서버 저장)
- 접근 경로: 로그인 후 계정 영역(`/account`로 추정). 홈의 '내 캐릭터' 카드와 가입 유도 팝업이 입구다.
- 기능 설명(공개 문구 기준): 캐릭터 소유를 인증하고, 부캐를 묶어 관리하고, API에 없는 스탯(F16)을 서버에 저장한다. 해방 일정 저장(F45), 내 정보 요약, 보스 클리어 스크린샷 제출(F31)도 여기서 한다. 인증된 캐릭터는 랭킹·상세에 인증 배지가 붙고, 수동 스탯이 모든 방문자에게 보인다.
- 입력 데이터: 인증 절차(방법 비공개), 수동 스탯, 스크린샷.
- 결과 데이터: 인증 배지, 부캐 목록(상세 '이력' 탭에 표시), 서버 저장 스탯.
- 화면 구성 핵심 요소: 확인 불가
- 필요한 공식 API(추정): `character/basic` 등. 소유 증명 수단은 목록 밖이라 별도 절차가 필요하다(추정).
- 추가 데이터·계산식: 확인 불가
- 구현 난이도: 상
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2. 인증 방식과 운영 정책부터 설계해야 한다.
- 확인 상태: 확인 불가(로그인 필요). 인증 방식은 공개 화면 어디에도 설명이 없었다.

#### F06. 홈 대시보드
- 접근 경로: `/`
- 기능 설명: 한 화면에 개인화(즐겨찾기·내 캐릭터), 소식(공지 4건, 다가오는 일정 날짜 칩 3개, 업데이트 내역 바로가기), 캐릭터 랭킹 위젯(월드·직업 필터, 8개 지표 탭, 상위 10), 길드 랭킹 위젯(조회수·지하수로·전장 탭), 빠른 가이드 카드 5개를 모았다. 맨 위에는 공지·문의·신기능 알림이 섞인 배너 캐러셀과 광고가 있다.
- 입력 데이터: 위젯 필터 클릭.
- 결과 데이터: 각 위젯 목록과 해당 페이지 링크.
- 화면 구성 핵심 요소: 2열 카드 그리드(데스크톱), 1열 적층(모바일).
- 필요한 공식 API(추정): 위젯별로 다르다(F28·F32·F55 참고).
- 추가 데이터·계산식: 없음
- 구현 난이도: 중
- 우리 사이트 유사 기능: 홈은 있다. 위젯 구성은 별도 비교가 필요하다.
- 우선순위 제안: P1. 개편 때 정보 구조를 다시 짤 기준으로 쓸 만하다.
- 확인 상태: 확인 완료

#### F07. 테마 3종 전환
- 접근 경로: 헤더 아이콘 버튼(모바일은 햄버거 메뉴).
- 기능 설명: 다크 → 파스텔(컵케이크) → 라이트 순으로 돌아가며 바뀌고, 선택은 브라우저에 저장된다.
- 입력 데이터: 버튼 클릭 / 결과 데이터: 화면 테마
- 화면 구성 핵심 요소: 아이콘 버튼, 다음 테마 이름을 알려 주는 툴팁.
- 필요한 공식 API(추정): 없음 / 추가 데이터: 없음
- 구현 난이도: 하
- 우리 사이트 유사 기능: 확인 필요(테마 저장 코드가 있다)
- 우선순위 제안: P3
- 확인 상태: 확인 완료

#### F08. 공지 웹 푸시 알림
- 접근 경로: 헤더 종 아이콘(모바일은 메뉴).
- 기능 설명: 공식 공지를 브라우저 푸시로 받는다. 일반 공지, 점검·패치, 이벤트 가운데 원하는 분류를 고른 뒤 구독한다. 권한이 막혀 있으면 브라우저 설정 방법을 안내한다.
- 입력 데이터: 분류 선택, 브라우저 알림 권한.
- 결과 데이터: 푸시 구독(수신 내용은 확인 불가).
- 화면 구성 핵심 요소: 작은 설정 패널(구독 상태, 체크박스 3개, 구독 버튼).
- 필요한 공식 API(추정): 공지 원천은 목록 밖(F55 참고). Web Push 발송 인프라가 필요하다.
- 추가 데이터·계산식: 없음
- 구현 난이도: 중
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2. 패치일 재방문 트리거로 쓸 수 있다.
- 확인 상태: 일부 확인. 테스트 브라우저의 알림 권한이 차단 상태라 구독과 수신은 하지 못했다.

#### F09. 홈 화면 앱 설치 안내(PWA)
- 접근 경로: 헤더 다운로드 아이콘(모바일은 메뉴 '앱 설치').
- 기능 설명: 브라우저별 설치 방법을 단계로 안내하는 모달이다.
- 입력 데이터: 없음 / 결과 데이터: 안내 문구
- 화면 구성 핵심 요소: 모달과 확인 버튼.
- 필요한 공식 API(추정): 없음 / 추가 데이터: 웹 앱 매니페스트, 서비스 워커(존재 여부는 미확인)
- 구현 난이도: 하
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2
- 확인 상태: 일부 확인(안내 모달만 봤다)

#### F10. 페이지 링크 복사와 URL 상태 반영
- 접근 경로: 대부분 페이지 제목 옆 '공유' 버튼(툴팁: 페이지 링크 복사).
- 기능 설명: 현재 주소를 복사한다. 랭킹·아이템 랭킹·길드 랭킹·통계·장기 미접속·아이템 DB는 필터와 페이지 번호가 쿼리스트링에 들어가 링크만으로 같은 화면이 재현된다. 계산기·캐릭터 비교는 입력을 바꿔도 URL이 그대로라 입력값이 공유되지 않는다.
- 입력 데이터: 클릭 / 결과 데이터: 클립보드 주소
- 화면 구성 핵심 요소: 제목 오른쪽 작은 버튼.
- 필요한 공식 API(추정): 없음 / 추가 데이터: 없음
- 구현 난이도: 하
- 우리 사이트 유사 기능: 부분(카카오 공유)
- 우선순위 제안: P1. 계산기 입력까지 URL에 담으면 상대보다 나은 공유가 된다.
- 확인 상태: 일부 확인. 버튼과 툴팁, URL 쿼리 반영은 확인했고, 복사 버튼은 누르지 않았다.

### 2-2. 캐릭터 상세·분석

캐릭터 상세 `/character/{월드}-{이름}`의 데스크톱 화면은 2단이다. 왼쪽에는 장비·요약 카드가 있고, 오른쪽에는 탭 16개(스탯 효율, 스탯, 보스, 경험치, 이력, 하이퍼, 스킬, 쥬얼, 링크, 유니온, 길드, 세트, 헥사, V매트릭스, 심볼, 기본정보)가 있다. 기본 탭은 '스탯 효율'이다. 모바일은 장비 카드 → 가로 스크롤 탭 바 → 패널 순서의 1단이다.

#### F11. 장비 영역(프리셋·안드로이드 슬롯·아이템 툴팁)
- 접근 경로: 캐릭터 상세 왼쪽 카드.
- 기능 설명: 장비 프리셋 1~3, 안드로이드 슬롯 전환, 착용 장비 그리드(아이콘 모서리에 문장 레벨, 잠재·에디 등급, 스타포스)를 보여 준다. 아이콘을 누르면 툴팁이 뜬다. 툴팁에는 템환산 점수(문장 포함/미포함), 착용 레벨, 가위 사용 횟수가 있고, 옵션은 기본·추가·잠재·에디·소울·문장으로 나뉘며 각 수치를 '기본+추가' 합으로 풀어 쓴다. 툴팁 안에서 장비 체험(F26)을 시작할 수 있다. 캐릭터 정보(레벨·경험치%, 직업, 길드 링크, 인증 배지, 전투력)와 몇 가지 수치(포스 등)는 장비 그리드 가운데에 있다.
- 입력 데이터: 프리셋·슬롯 선택, 아이콘 클릭.
- 결과 데이터: 프리셋별 장비와 툴팁 상세.
- 화면 구성 핵심 요소: 장비 그리드 가운데 아바타, 상단 버튼 줄(프리셋, 안드로이드, 갱신, 보스 세팅, 스냅샷, 즐겨찾기, 공유).
- 필요한 공식 API(추정): `item-equipment`(프리셋 포함), `android-equipment`, `cashitem-equipment`(코디), `stat`, `character/basic`, `guild`.
- 추가 데이터·계산식: 템환산(F13), 아이템 아이콘·후보 DB(F37 연동).
- 구현 난이도: 중
- 우리 사이트 유사 기능: 있음(장비·캐시·안드로이드·프리셋·툴팁, 아이템 공유 이미지). 템환산 점수는 없다.
- 우선순위 제안: P0. 동등 수준을 유지하는 영역이다.
- 확인 상태: 확인 완료(프리셋을 바꾸면 장비 구성, 전투력, 드롭률 같은 옵션 수치가 함께 바뀌는 것 확인).

#### F12. 옵션 요약 패널
- 접근 경로: 캐릭터 상세 왼쪽, 장비 그리드 아래.
- 기능 설명: 잠재·에디의 '물리 대미지+보스 공격력' 합을 따로 또 같이 보여 주고, 펼치면 물댐·보공을 나눈다. 아래에 방어율 무시, 아이템 드롭률, 메소 획득량, 최대 대미지, 경험치·파티 경험치 획득량이 한 블록으로 있다. 프리셋을 바꾸면 함께 바뀐다(사냥 프리셋이면 드롭률이 올라간다).
- 입력 데이터: 프리셋, 펼치기.
- 결과 데이터: 합산 % 값.
- 화면 구성 핵심 요소: 3열 표(잠재/에디/합산)와 6칸 수치 블록.
- 필요한 공식 API(추정): `item-equipment`, `stat`.
- 추가 데이터·계산식: 장비 옵션 합산 규칙(어떤 옵션을 같은 계열로 묶는지).
- 구현 난이도: 중
- 우리 사이트 유사 기능: 부분(스탯 표시). 잠재·에디 합산 요약은 확인 필요.
- 우선순위 제안: P1. 랭킹 지표(잠재·에디·아드·메획)와 같은 정의라 함께 설계해야 한다.
- 확인 상태: 확인 완료

#### F13. 템환산 점수
- 접근 경로: 아이템 툴팁, 캐릭터 기본정보 '최고 기록', 랭킹·아이템 랭킹·비교·장비 추적기의 정렬 기준.
- 기능 설명: 장비 한 부위의 옵션을 점수 하나로 환산한다. 캐릭터 합계는 문장 포함/미포함 두 가지다. 상위권 무기 한 개가 약 650점, 캐릭터 합계는 문장 포함 약 2,000점 수준이다.
- 입력 데이터: 장비 옵션 전부.
- 결과 데이터: 부위별 점수, 합계 2종.
- 화면 구성 핵심 요소: 툴팁 오른쪽 위 숫자 2개, 랭킹 표의 열.
- 필요한 공식 API(추정): `item-equipment`.
- 추가 데이터·계산식: 산식은 공개되지 않았다. 이름으로 보아 주요 옵션을 기준 스탯으로 환산해 합한 자체 점수로 추정한다.
- 구현 난이도: 상(공정한 환산 계수 설계·검증·직업별 차이)
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P1. 도입한다면 환산 계수와 버전을 공개해 투명성으로 차별화하는 것을 권한다.
- 확인 상태: 일부 확인(값·정렬은 확인, 산식 비공개)

#### F14. 스탯 효율(전투력/대미지 효율 환산)
- 접근 경로: 캐릭터 상세 '스탯 효율' 탭(기본 탭).
- 기능 설명: 기준 스탯과 수치(예: 최종 대미지 1%)를 고르면, 그만큼 올렸을 때 오르는 전투력(절대값과 비율)과 같은 효과를 내는 다른 스탯의 양(치명타 피해 %, 공격력 %, 물리 대미지, 보스 공격력, 깡공격력, 최대 대미지)을 막대그래프로 보여 준다. 모드는 두 가지다. '대미지 효율' 모드에서는 버프 소모품·이벤트 버프 같은 도핑 항목을 체크해 합산하고, 보스별 방어율을 골라 스탯마다 "+1%당 최종 피해 증가율"을 낸다.
- 입력 데이터: 기준 스탯, 수치, 모드, 도핑 체크, 보스 방어율.
- 결과 데이터: 오르는 전투력·대미지 효율, 스탯별 등가량, +1%당 효율.
- 화면 구성 핵심 요소: 상단 입력 줄, 결과 숫자, 정렬된 막대 목록, 도핑 체크 패널.
- 필요한 공식 API(추정): `stat`, `item-equipment`, `hyper-stat`, `link-skill`, `user/union`, `user/union-raider`, `guild`, `hexamatrix-stat`, `symbol` 등 전투력 구성 요소 전부.
- 추가 데이터·계산식: 전투력·대미지 계산 모델이 공개되지 않았다(자체 추정 모델). 적용 패치 버전 표기도 없다. 보스 방어율 목록과 도핑 항목 수치는 게임 데이터다.
- 구현 난이도: 상
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P1. 사용자 의사결정에 직결되는 차별화 기능이다. 산식과 기준 패치를 함께 공개하는 쪽을 권한다.
- 확인 상태: 확인 완료(모드 전환, 도핑·보스 선택 UI, 결과 변화 관찰). 산식은 비공개.

#### F15. 스탯 출처별 기여도 상세
- 접근 경로: 캐릭터 상세 '스탯' 탭에서 스탯 행 선택.
- 기능 설명: 주요 스탯 8개(공격력, 공격력%, 대미지, 보스 공격력, 치명타 피해, 최대 대미지, 최종 대미지, 방어율 무시) 가운데 하나를 고르면 출처별로 나눈다. 장비(기본·추가·소울·세트·스타포스 강화 옵션, 장비명 단위), 스킬(패시브·해방 무기), 콘텐츠(하이퍼, 링크, 유니온 등)로 구분한다.
- 입력 데이터: 스탯 선택.
- 결과 데이터: 계층형 분해 목록.
- 화면 구성 핵심 요소: 왼쪽 스탯 목록, 오른쪽 분해 패널(선택 전에는 안내 문구).
- 필요한 공식 API(추정): `item-equipment`, `set-effect`, `hyper-stat`, `link-skill`, `user/union`, `user/union-raider`, `guild`, `skill-equipment`, `hexamatrix-stat`, `symbol`.
- 추가 데이터·계산식: 패시브 스킬 수치 같은 게임 데이터 테이블.
- 구현 난이도: 중(우리는 일부 이미 구현)
- 우리 사이트 유사 기능: 있음(주요 스탯 출처별 분해, 접기/펼치기).
- 우선순위 제안: P1. 이미 가진 기능이라 장비명 단위 분해와 계층 표시만 보강하면 된다.
- 확인 상태: 확인 완료

#### F16. API 밖 스탯 수동 입력 칩
- 접근 경로: 캐릭터 상세 오른쪽 탭 위의 칩 줄. 항목은 스타코러스, 성흔, 축복, 펫, 유니온 챔피언, 명예 배지, 몬스터 컬렉션.
- 기능 설명: 공식 데이터로 알 수 없는 성장 요소를 직접 입력해 전투력 계산에 반영한다. 칩마다 해당 요소가 더하는 전투력이 표시된다. 스타코러스는 노드 그래프(개방 수·누적 개방 비용)로, 성흔은 보스·등급·색을 고르는 방식으로, 유니온 챔피언은 1~4번 챔피언 등급을 고르는 방식으로 입력한다. 미인증 캐릭터는 보는 사람의 브라우저에만 저장되고("로컬 저장" 표기), 인증 캐릭터는 소유자가 서버에 저장한 값이 모두에게 보인다("서버 저장" 표기). 초기화와 '전부 열기'를 지원한다.
- 입력 데이터: 항목별 선택값.
- 결과 데이터: 항목별 전투력 기여, 스탯 효율·보스 세팅 재계산.
- 화면 구성 핵심 요소: 체크 아이콘이 달린 칩, 펼침 패널(그래프형 또는 선택형).
- 필요한 공식 API(추정): 목록 밖 → 사용자 입력이 필요하다(추정). 경쟁사도 전부 입력 항목으로 다룬다. 펫은 `pet-equipment`로 일부 대체할 수 있을지 검토가 필요하다.
- 추가 데이터·계산식: 항목별 효과 수치표(게임 데이터).
- 구현 난이도: 상(입력 UX, 저장소, 소유자 검증)
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2. 정확도는 올라가지만, 로그인이 없으면 로컬 저장으로만 운영된다.
- 확인 상태: 일부 확인. 인증·미인증 캐릭터의 표시 차이와 로컬 저장 키 생성은 확인했다. 값 입력과 서버 저장은 하지 않았다.

#### F17. 보스 세팅
- 접근 경로: 캐릭터 상세 상단 '보스 세팅' 토글.
- 기능 설명: 장비·안드로이드·하이퍼·링크·유니온 프리셋 조합 가운데 보스용 세팅을 구성해 전투력과 옵션 요약을 다시 계산한다(업데이트 내역 10/20). 켜고 끄면 전투력·방무·드롭률·최대 대미지가 바뀐다.

- 필요한 공식 API(추정): 프리셋 정보가 담긴 `item-equipment`, `android-equipment`, `hyper-stat`, `link-skill`, `user/union`.
- 추가 데이터·계산식: 조합 선택 규칙은 공개되지 않았다(최대 전투력 조합으로 추정).
- 구현 난이도: 상
- 우리 사이트 유사 기능: 부분(프리셋 개별 전환)
- 우선순위 제안: P1
- 확인 상태: 확인 완료(토글에 따른 수치 변화)

#### F18. 보스 입장 전투력 표
- 접근 경로: 캐릭터 상세 '보스' 탭.

- 화면 구성 핵심 요소: 요약 수치와 표(가능 행 강조).

- 확인 상태: 확인 완료

#### F19. 경험치 성장 기록
- 접근 경로: 캐릭터 상세 '경험치' 탭.
- 기능 설명: 날짜별 레벨·경험치%·누적 경험치를 표로 보여 주고, 최근 7~8일 추이를 선 그래프로 그린다. 같은 날 다시 조회하면 그날 값이 최신으로 덮인다(하루 1점).
- 입력 데이터: 없음(조회 시점 스냅샷).
- 결과 데이터: 일별 레벨, 경험치%, 누적 경험치.
- 화면 구성 핵심 요소: 선 그래프와 표.
- 필요한 공식 API(추정): `character/basic`(경험치, 레벨). 이력은 자체 저장이다.

- 필요한 공식 API(추정): `guild/id`, `guild/basic`(길드원 목록, 스킬·어빌리티 포함 여부 확인 필요), `ranking/sharenian-*`. 길드원 스펙은 각 멤버의 캐릭터 엔드포인트(자체 DB).

- 구현 난이도: 중
- 우리 사이트 유사 기능: 부분(길드 조회 있음)
- 우선순위 제안: P1. 길드원 스펙 표와 정렬은 길드장·길드원 수요가 크다.
- 확인 상태: 확인 완료(탭 3개와 정렬 확인. 전체 갱신은 누르지 않음)

#### F35. 캐릭터 비교
- 접근 경로: `/compare`(입력 후에도 URL은 그대로)
- 기능 설명: 두 캐릭터(월드+닉네임)를 불러 템환산 합계 점수와 차이를 보여 준다. 문장 포함/미포함 전환과 '어느 쪽 우위' 필터가 있다. 비교 기준은 각 캐릭터의 보스 세팅 장비이고, 부위별 아이템명·점수·차이를 나란히 놓는다. HEXA 코어 레벨 비교도 있다. 슬롯마다 비교 대상을 제거할 수 있다.
- 입력 데이터: 월드 2개, 닉네임 2개.
- 결과 데이터: 합계 점수와 차이, 부위별 비교, HEXA 비교.
- 화면 구성 핵심 요소: 좌우 입력 카드, 중앙 차이 열이 있는 3열 표.
- 필요한 공식 API(추정): `id`, `character/basic`, `item-equipment`, `hexamatrix-skill`(두 캐릭터 각각)
- 추가 데이터·계산식: 템환산(F13), 보스 세팅(F17)
- 구현 난이도: 중
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P1. URL에 두 캐릭터를 담아 공유할 수 있게 하면 상대보다 낫다.
- 확인 상태: 확인 완료(2명 비교 결과 확인). 비교를 실행하면 사이트가 별도 비교 로그를 전송하려 했다(차단됨). 인기 비교 조합 같은 집계에 쓰는 것으로 보인다(추정).

### 2-5. 수집 데이터 기반 도구·통계

#### F36. 장비 추적기
- 접근 경로: `/item-tracker`(메뉴 NEW 배지)
- 기능 설명: 사이트가 수집한 모든 캐릭터의 장비·코디 아이템을 조건으로 찾는다. 조건은 아이템 이름, 종류(장비/코디), 월드, 부위, 스타포스 범위, 착용 레벨 범위, 캐릭터 최소 레벨이다. 접힌 패널에서 잠재·에디·추가 옵션(옵션, 수치, 이상/같음/이하)과 소울(보스 20종·옵션)·문장(5종·레벨)도 지정할 수 있다. 결과는 템환산 기준으로 정렬하고, 행을 누르면 상세가 열리며 캐릭터 상세로 바로 간다. 링크 공유를 지원한다. 이름 '제네시스'로 검색하면 991건이 나왔다.
- 입력 데이터: 위 조건들.
- 결과 데이터: 아이템, 서버·캐릭터, 스타포스/착용 레벨, 점수 2종.
- 화면 구성 핵심 요소: 2단 필터 폼(기본 조건과 접히는 고급 조건 4개), 결과 표.
- 필요한 공식 API(추정): 자체 DB(`item-equipment`, `cashitem-equipment` 스냅샷)
- 추가 데이터·계산식: 옵션 정규화 사전(옵션명·수치 파싱)
- 구현 난이도: 상
- 우리 사이트 유사 기능: 없음
- 우선순위 제안: P2. 수집 규모가 받쳐 줘야 쓸모가 생긴다.
- 확인 상태: 확인 완료(이름 검색 1회)

- 입력 데이터: 종류, 부위, 이름, 스타포스 단계 선택.
- 결과 데이터: 단계별 기본 옵션 수치.
- 화면 구성 핵심 요소: 카드 그리드(20개씩)
- 필요한 공식 API(추정): 자체 DB(`item-equipment` 스냅샷에서 아이템·스타포스별 기본 옵션 추출)

- 우리 사이트 유사 기능: 없음

- 확인 상태: 일부 확인(목록 확인. 스타포스 단계 버튼을 눌렀을 때의 변화는 텍스트상 감지하지 못함)

### 3-3. UX 장점(경쟁사)
- 분석(상세 탭) → 판단(스탯 효율, 장비 체험, 보스 세팅) → 계획(계산기) → 재미(시뮬레이터) → 비교·자랑(비교, 스냅샷, 위업)이 한 사이트 안에서 이어진다.
- 캐릭터 상세의 기본 탭을 '스탯 효율'로 둬서, 들어오자마자 "무엇을 올릴까"에 답한다.
- 로그인 없이 즐겨찾기·최근 조회·수동 입력(로컬 저장)을 쓸 수 있어 진입 장벽이 낮다. 로그인하면 서버 저장과 인증 배지로 확장된다.
- 지표 정의를 툴팁으로 노출한다(헥사, 잠재·에디 합산, 갱신 범위).
- 통계 화면은 집계 기준 주석을 성실하게 단다.
- 필터 상태가 URL에 반영돼 공유와 뒤로 가기가 자연스럽다.
- 10일 연속으로 기능을 추가했고, 그 내역을 날짜별로 공개한다.
- 푸시, 홈 화면 설치, 실시간 티커처럼 재방문을 부르는 장치가 여럿 있다.

### 3-4. UX 단점(경쟁사)
- 계산 근거가 공개되지 않는다. 템환산 점수, 전투력·대미지 모델, 보스 세팅 조합 규칙의 산식이 없다. 계산기·시뮬레이터에는 확률 출처와 적용 패치 버전이 적혀 있지 않다.
- 데이터 일관성이 약하다. 헥사 소모량 가이드 합계와 헥사 기간 계산기 결과가 다르고, 헥사 스탯 가이드 표에는 단조 증가가 깨지는 값이 있다. 장비 체험을 아무것도 바꾸지 않고 시작해도 전투력이 약 0.4% 어긋난다.
- 랭킹의 범위와 시점이 불명확하다. 캐릭터 랭킹 화면은 "사이트에서 조회된 캐릭터만"이라는 범위를 알리지 않는다(아이템 랭킹·통계에는 있다). 기준 시각과 순위 변동도 없다.
- 레벨·유니온·업적 같은 공식 랭킹을 제공하지 않는다. 전체 인구 기준 순위가 필요하면 다른 사이트로 가야 한다.
- 광고와 팝업이 촘촘하다. 특히 모바일은 하단 고정 광고와 가입 시트가 겹친다.
- 모바일에서 확대를 막았고, 넓은 표는 가로 스크롤에 의존한다.
- 계산기 입력을 링크로 공유할 수 없다. 캐릭터 데이터로 계산기를 미리 채우는 연동도 없다(헥사·세트·길드 어빌리티·심볼).
- 공유 시트를 지원하지 않는 환경에서는 자동 복사가 없고, 카카오 공유도 관찰 범위에서는 없었다.
- 아이콘만 있는 버튼이 많아 툴팁에 기대야 의미를 안다.

### 3-5. 우리가 더 잘할 수 있는 점
1. 근거 공개: 모든 점수·계산·시뮬레이션에 산식 요약, 데이터 출처(공식 확률 공지 링크 등), 적용 패치 버전, 마지막 검수일을 단다. 계산 기준이 바뀐 이력은 따로 페이지로 둔다.
2. 단일 게임 데이터 원천: 가이드·계산기·캐릭터 요약이 같은 표(헥사 비용 등)를 쓰게 하고, 합계·단조성 자동 검증을 테스트에 넣는다.
3. 랭킹 이원화: 우리 강점인 공식 랭킹(전체 인구)과 수집 기반 스펙 랭킹을 나눠 표기한다. 둘 다 기준 시각, 수집 범위, 전일 대비 순위 변동을 보여 준다.
4. "내 캐릭터로 계산": 상세에서 계산기로 넘어갈 때 현재 헥사 레벨, 세트 구성, 심볼 진행, 길드 어빌리티를 자동으로 채운다. 경쟁사에 없는 연결이다.
5. 성장 추적 강화: 이미 쌓고 있는 스냅샷으로 일·주·월 성장량, 레벨업 예상일, 전투력 변화 그래프, 장비 변경 타임라인을 만든다.
6. 신선도 표준화: 모든 카드에 '기준 시각'을 달고, 갱신 버튼에 쿨다운과 남은 시간을 표시하고, 실패하면 안내한다.
7. 공유: 보유한 카카오 공유와 이미지 카드에 더해 계산기·비교 상태까지 URL로 공유되게 한다.
8. 모바일: 확대를 허용하고, 넓은 표는 모바일에서 카드형으로 바꾸고, 광고가 콘텐츠를 가리지 않게 배치 원칙을 정한다.
9. AI 챗봇(보유, 동작 확인 선행): 계산 근거 설명, "다음 강화 우선순위" 같은 대화형 분석으로 차별화한다. 경쟁사에는 없다.
10. 월드 커버리지: 경쟁사 월드 선택지는 7개였고 챌린저스 월드는 없었다(관찰). 신규·이벤트 월드를 빨리 지원하면 차별점이 된다.

## 5. V매트릭스 규칙 대조(추가 조사, 2026-10-28)

질문별 결과:
1. V코어가 공격력 %(또는 다른 스탯)의 출처로 나오는가: 명시적으로는 나오지 않는다. 코어별 값도 없다. V코어 효과를 반영했다면 '스킬 > 패시브' 합계 안에 섞였을 가능성만 남는다. 마법 공격력 %의 패시브 300%는 다른 스탯의 패시브(10~60%)보다 유난히 크다.
2. 25% 상한이나 레벨별 산식: 화면 어디에도 없다.
3. 고정 기본 효과 4종: 이름 붙은 출처로는 하나도 보이지 않는다. 보스 공격력의 스킬(패시브) 합계가 10%뿐이라 윈드 부스터 +12%를 그대로 반영했다고 보기는 어렵다. 나머지 3종은 패시브 합계에 섞였는지 판별할 수 없다.
4. 마법 공격력 % 총합: 경쟁사 503%, 우리 405%(규칙 적용)·143%(V매트릭스 제외). 우리 규칙의 V 몫은 10코어 × 25% + 블레스 12% = 262%다. 경쟁사 패시브 300%를 '262% + 기타 38%'로 설명할 수는 있지만 증거는 아니다. V와 무관한 부분(장비+콘텐츠)도 경쟁사 203%와 우리 143%로 차이가 커서 항목별 대조가 따로 필요하다.

- 스탯 효율 탭: V코어 언급이 없다. 최종 대미지 1%와 같은 가치로 제시하는 마법 공격력 %가 전투력 모드 1.86%, 대미지 효율 모드 8.51%로 서로 다르다. 503%를 곱연산 기준으로 쓴 값(약 6.0%)과도 맞지 않아 역산 근거가 되지 않는다.
- 결론: 경쟁사 화면만으로는 우리 규칙(레벨당 0.6%, 상한 25%, 고정 기본 효과)을 확인하지도 반박하지도 못한다. 공식 근거로 확정하기를 권한다. 확인할 곳은 게임 내 코어 설명과, 공식 패치노트 목록에 있는 2026-07-09 패치노트(제목에 'V매트릭스' 포함)다.
