# 우리 스탯 계산과 두 사이트 규칙의 차이

- 작성일: 2026-10-28
- 비교 대상(우리): `src/controllers/maplestorym.controller.js`의 `buildMajorStats`와 `collect*` 함수, `src/config/starforce-set-options.js`, `public/js/pages/character.js`의 `HEXA_CORE_CUMULATIVE_COST`
- 비교 대상(그쪽): `maplemtool.md`, `maplemworlds.md`(2026-10-28 공개 JS 분석)
- 줄 번호는 2026-10-28 작업 트리 기준이다. 같은 날 다른 세션이 컨트롤러의 랭킹·전투력 표시 부분을 고치고 있지만, 아래에 적은 합산 함수는 바뀌지 않았다. 줄이 밀릴 수 있으니 함수 이름으로 찾는 편이 낫다.
- 판단 기준: 두 사이트가 같은 규칙이나 값을 쓰면 "두 사이트 일치"로 적었다. 넥슨 API 응답으로 직접 확인한 것은 "API로 확인"이라고 따로 적었다. 공식 수치 대조는 이 문서 범위 밖이다.

## 1. 요약

우리 계산은 두 사이트보다 주요 스탯이 대체로 낮고, 방어율 무시는 반대로 지나치게 높다. 고정 데이터 5명으로 보면 최대 대미지가 3억~19억 적고, 같은 전투력 공식에 넣으면 전투력이 maplemtool 규칙 대비 0.50~0.62배다(3장).

차이가 큰 순서:

1. 최대 대미지 기본값 1억 → 두 사이트 모두 4억
2. 문장 옵션 미반영 → 두 사이트 모두 반영(무자비한 문장 Lv.10 하나가 최대 대미지 1억 1,900만)
3. 장비 기본 옵션과 추가 옵션 이중 합산 → 두 사이트 모두 기본 옵션에서 같은 스탯의 추가 옵션을 뺀다(API로 확인)
4. 방어율 무시 단순 합 → 두 사이트 모두 곱연산(우리 값이 100%를 넘는 캐릭터가 있다)
5. 아케인셰이드 스타포스 세트 최대 대미지가 두 사이트 값의 2/3
6. 직업 패시브, 솔 야누스, 제네시스 무기, 본인 링크, 쥬얼이 빠져 있다
7. 길드 어빌리티 중 지하수로·전장 전용 효과를 넣고 있고, "물리 … 및 마법 …" 묶음 문구는 물리 쪽만 읽는다

## 4. 우리와 같은 것(신뢰도 확인용)

- 한벌옷 스타포스 2배, 세트 스타포스 합계로 구간 선택(두 사이트 일치)
- 앱솔랩스·도전자의 장비 스타포스 표, 루타비스 유니크 값(maplemtool과 일치)
- V 코어 레벨당 공격력% 공식(Lv.1 7.6, Lv.30 25), 기본 효과 4종을 넣지 않는 현재 설정(maplemtool과 일치)
- HEXA 스탯 `activate_flag`="1" 코어만, 하이퍼·링크 사용 프리셋, 유니온 스탯 API(`use_union_stat`) 사용
- 트리 오브 스타라이트의 조건부 최종 대미지 제외(두 사이트도 넣지 않음)
- 칭호·훈장은 장비 칸으로 반영(두 사이트 같음)
- HEXA 비용표의 오리진·마스터리·강화 30레벨, 공용 10레벨까지 모든 칸

## 5. 맞출 때 참고할 점

- 1·3·4·19번은 두 사이트가 같고 API로도 뒷받침되는 항목이라 먼저 맞춰도 위험이 낮다.
- 5~10번(패시브 묶음)은 maplemtool 방식(직업 표 + V·솔 야누스·제네시스를 API에서 계산)이 캐릭터별 차이를 반영한다. 값은 `job-passives.json`, `vmatrix.json`에 있다.
- 15번(성흔 세트)과 18번(깡공)은 우리 화면 설계에 따라 고를 문제다. 수동 입력을 두지 않는다면 API 성흔 세트를 그대로 두는 편이 낫다.
- 23번(레이븐혼 등)은 두 사이트 어디에도 없으니 게임 안에서 확인해야 한다.
- 화면에 전투력을 보여 준다면 공식은 두 사이트와 같은 것을 쓰고, API 능력치의 "전투력"과 다르다는 점을 안내해야 한다.
