# maplemtool.com 공개 JS로 본 스탯·전투력 규칙

- 작성일: 2026-10-28
- 대상: maplemtool.com(메엠툴)이 브라우저에 내려주는 공개 JS 번들과 데이터 테이블 JSON
- 목적: 그 사이트가 캐릭터 스탯 합산, 최대 대미지, 전투력, 스탯 환산, HEXA·심볼·해방 계산에 쓰는 규칙과 상수를 우리 말과 표로 정리한다. 우리 사이트(maplem.co.kr) 스탯 계산을 다시 맞출 때 대조 자료로 쓴다.
- 원칙: 값과 규칙만 옮겼다. 코드는 근거 추적용으로 한두 줄만 발췌했다. 위치는 원본 파일명과 검색용 앵커 문자열로 적었고, 앵커는 원본(압축된) 파일에서 정확히 한 번 나오는 것을 스크립트로 확인했다. "pretty L번호"는 js-beautify로 정리한 사본의 줄 번호다. 데이터 테이블은 `tables.d39c9358b9414219.json → <테이블 이름>`으로 적었다.
- 이 문서의 수치는 그 사이트가 쓰는 값이다. 게임 공식 값인지는 따로 확인하지 않았다. 그 사이트가 각 행에 직접 단 출처 표기(source·patch·confidence)는 6장에 모았다.
- 같은 날 조사한 maplemworlds.kr 규칙은 `maplemworlds.md`, 우리 코드와 다른 값은 `diff-vs-ours.md`에 있다. 두 사이트 차이는 이 문서 7장에 정리했다.

### 0.2 수집·분석 방법

- Headless Chromium으로 홈과 캐릭터 화면(유니온/피카츄)을 한 번씩 열고, 그때 받은 JS와 JSON만 저장했다. maplemtool.com으로 가는 GET 외 요청과 분석 비컨은 브라우저에서 막았다. 그 사이트 API 응답은 저장하지 않았다.
- js-beautify로 정리한 뒤 한글 라벨과 내보내기 이름(`extract`, `combatPower`, `statEfficiency` 등)으로 로직을 따라갔다.
- 번들 안의 상수 덩어리(HEXA 스탯 값표 등)는 직접 만든 리터럴 파서로 JSON만 뽑았다. 그 사이트 코드는 실행하지 않았다.
- 규칙을 제대로 읽었는지 확인하려고, 읽은 규칙을 우리가 다시 구현해 우리 고정 데이터(`test/fixtures/characters`, 2026-10-28 캡처)에 넣어 봤다. 디올의 "조회 당시 착용 조합" 전투력은 이 재구현이 64,080,892, 이전 조사 때 그 사이트 화면값이 64,096,437로 0.02% 차이였다(부록 B).

### 0.3 핵심 요약

1. **최대 대미지 기본값은 4억**이다. "캐릭터 기본" 그룹에 고정으로 넣고, 그 사이트 표기는 `source: "user-confirmed", patch: "2026-09", confidence: 1`이다. 수동 입력으로 덮지 못한다.
2. **전투력** = `floor( 깡공 × (공% + 0.3×(1+보공)) × (1+대미지) × (1.2+치피) × (1+최종) × (최대 대미지/1억)^0.2 )`. 방어율 무시와 치명타 확률은 들어가지 않는다. maplemworlds와 같은 식이다(반올림만 다름).
3. **직업 패시브**는 34개 직업별 표가 있다(만렙 기준). 표에 없는 15개 직업은 추정 기본값을 쓴다. 대부분 직업이 공격력% 50, 대미지 35, 보공 10, 치피 30, 최종 10으로 같다.
4. **V매트릭스**: 장착한 공용 코어 10종마다 공격력% `7 + 0.6×레벨`(Lv.30 = 25), 직업 계열 공용 코어 하나에 대미지 `16 + 0.3×레벨`. 기본 효과(+9/+12)는 없다. 판테온은 목록에 없다.
5. 패시브 묶음에 **솔 야누스**(Lv.30 최종 30%)와 **제네시스 무기**(최종 +10%)가 들어간다. **본인 링크 스킬**(캐릭터 Lv.70/120/260 → 링크 Lv.1/2/3)도 따로 더한다.
6. **장비 기본 옵션 값에는 같은 스탯의 추가 옵션이 이미 합쳐져 있다**고 보고 뺀다. 우리 고정 데이터로 확인했다(1.3).
7. **문장(emblem) 옵션**과 **쥬얼**을 합산한다. 문장은 최대 대미지 비중이 크다(무자비한 문장 Lv.10 = 1억 1,900만).
8. **방어율 무시는 곱연산**이다. 장비는 아이템 단위, 세트는 세트 단위로 먼저 더한 뒤 곱한다.
9. **스타포스 세트 옵션**은 자체 표 7종으로 계산한다. 아케인셰이드 최대 대미지는 우리 표의 정확히 1.5배이고, 루타비스 레전더리와 160제 세트 표가 우리에게 없다.
10. 길드는 **어빌리티(지하수로·전장 전용 제외)와 개인 스킬만** 넣는다. 길드 공용 스킬(`guild_skill`)은 쓰지 않는다.
11. API 밖 항목(성흔, 명예 배지, 몬스터 컬렉션, 축복, 유니온 챔피언, 스타코러스, 펫, 길드 요리)은 **기본값 0**인 수동 입력이다.

## 1. 주요 스탯 합산 규칙

캐릭터 화면의 능력치, 전투력, 보스 프리셋, 성장 시뮬레이터가 모두 한 함수(`extract`)의 결과를 쓴다.

- 출처: `app.3b4c69e71622b30c.js`, 앵커 `function Tn(a,o={}){` (pretty L3174). 출처별 집계 함수는 앵커 `function Bt(a,o={},i=oe,l={}){` (pretty L1188).

### 1.1 대상 스탯과 합계 방식

- 키 11개: 물리 공격력, 마법 공격력, 물리 공격력%, 마법 공격력%, 물리 대미지, 마법 대미지, 보스 공격력, 치명타 피해, 최대 대미지, 최종 대미지, 방어율 무시(앵커 `$r=["물리 공격력","마법 공격력","물리 공격력%"`).
- 물리·마법은 직업 계열 표(`msm-class-elements.json`, 49개 직업)로 정한다. 마법 계열은 비숍, 캡틴, 플레임위자드, 에반, 루미너스, 아크메이지 2종, 배틀메이지, 메카닉, 엔젤릭버스터, 키네시스, 시아, 라라, 일리움이다. 표에 없으면 깡공이 큰 쪽으로 정하고 경고를 낸다.
- 방어율 무시 외에는 단순 합이다(소수 여섯째 자리 반올림).
- 방어율 무시는 그룹별로 먼저 더한 뒤 곱한다: `총방무 = 1 − Π(1 − min(100, 그룹합)/100)`.
  - 발췌: `xt.total=(1-Et.reduce((wt,_t)=>wt*(1-Math.min(100,_t)/100),1))*100` (pretty L1269)
  - 그룹: 장비 옵션은 **아이템 이름**(한 아이템의 기본·추가·잠재·에디 방무는 먼저 더함), 세트 효과는 **세트 이름**(같은 세트의 스타포스 옵션 방무와 합쳐짐), **쥬얼 세트·HEXA 스탯·축복**은 한 그룹(앵커 `rt="쥬얼세트·HEXA 스탯·빛의 성소 : 축복"`), 나머지는 출처 이름.
  - 단순 합(`additiveNaive`)도 함께 계산하지만 표시용이다.
- 깡공은 API 능력치 값을 쓰지 않는다. 출처 합에 레벨 기본 공격력(1.13)을 더해 직접 만들고, API 값과의 차이(`statApiDiff`)는 기록만 한다.

### 1.3 장비 옵션(기본·추가·잠재·에디셔널)

- 잠재·에디셔널·추가 옵션은 줄마다 그대로 더한다.
- **기본 옵션 보정**: 기본 옵션 줄 값에서 같은 이름·같은 단위(%, 정수)의 추가 옵션 합을 뺀 값을 "장비:기본"으로 더한다(앵커 `function Ut(a,o){`, pretty L1067). 추가 옵션은 "장비:추가"로 따로 전부 더하므로, 한 아이템의 합계는 `기본 옵션 + (기본 옵션 목록에 없는 스탯의 추가 옵션)`이 된다.
- 이 규칙은 넥슨 API 응답과 맞는다. 우리 고정 데이터로 확인한 예:

| 캐릭터·아이템 | 아이템 고유 옵션(`item_option`) | 기본 옵션 | 추가 옵션 | 해석 |
|---|---|---|---|---|
| 디올 · 루즈 컨트롤 머신 마크 | 최종 대미지 5% | 최종 대미지 17.80% | 최종 대미지 6.40% × 2 | 5 + 12.8 = 17.8. 추가 옵션이 기본 줄에 이미 들어 있다 |
| 디올 · 마력이 깃든 안대 | 치명타 피해 15% | 최종 대미지 줄 없음 | 최종 대미지 6.10% × 2 | 기본 목록에 같은 스탯이 없어서 따로만 나온다 |
| 성령 · 거대한 공포 | 방어율 무시 2% | 물리 대미지 35.60% | 물리 대미지 15.59% | 고유 옵션엔 없지만 스타포스로 생긴 물리 대미지 줄에 합쳐졌다 |
| 성령 · 제네시스 그람 | 물리 공격력 51,123 | 물리 공격력 103,636 | 물리 공격력 5,982 | 깡공도 같은 방식 |

### 1.4 문구 파서

앵커 `function pt(a){` (pretty L912). 모든 문구 출처가 같은 파서를 쓴다.

- "(다음 레벨: …)" 괄호를 지우고, 줄바꿈과 ", "(쉼표+공백)로 나눈다. "1,500"처럼 공백 없는 쉼표는 천 단위로 본다.
- 한 조각을 `이름: 값`, `이름 값% 증가`, `이름 값` 가운데 맞는 형식으로 읽는다.
- 이름에 " 및 "이나 " / "가 있으면 나눠서 양쪽에 같은 값을 넣는다. "물리/마법 공격력"처럼 붙은 형태도 "물리 공격력", "마법 공격력"으로 나눈다.
  - 예: 길드 개인 스킬 "물리 공격력 및 마법 공격력 7.5% 증가" → 물리 공격력% 7.5, 마법 공격력% 7.5
- 물리·마법 공격력(그리고 방어력, 최대 HP·MP)은 값에 %가 붙으면 "…%" 키가 된다. 다른 스탯은 이름 그대로다.
- 이름은 정확히 같아야 잡힌다("보스 몬스터 공격 시 대미지" 같은 다른 표기는 안 잡힌다). "만" 같은 단위 글자는 해석하지 않는다.

### 1.5 아이템 세트 효과

- 선택한 장비 프리셋이 API의 사용 중 프리셋이면 set-effect API의 `set_info` 문구를 그대로 쓴다. 다른 프리셋을 계산할 때만 자체 표(`msm-set-effects.json`, 세트 40개)로 개수와 효과를 만든다. 이때 표에 없는 세트는 빠진다는 경고를 낸다.
- **성흔 세트는 뺀다.** 세트명에 "성흔"이 들어간 API 세트(예: "초록빛 성흔 2세트 (유니크)")는 합산에서 제외하고, 성흔은 수동 입력으로 받는다(앵커 `Qe=ya=>/성흔/.test(ya?.set_name||"")`).

### 1.6 스타포스 세트 옵션

자체 표(`msm-starforce-sets.json`)로 계산해 "보정:세트명"으로 더한다. API set-effect 응답에는 스타포스 옵션이 없다(앵커 `function za(a,o,{adjust:i}={}){`, pretty L1526).

### 1.8 V매트릭스

앵커 `function wo(a,o,i={}){` (pretty L1586). 결과는 직업 패시브와 함께 "스킬 패시브" 한 그룹에 들어간다.

- 공용 코어 10종(블링크, 로프 커넥트, 쓸만한 샤프 아이즈, 쓸만한 홀리 심볼, 쓸만한 컴뱃 오더스, 쓸만한 윈드 부스터, 쓸만한 어드밴스드 블레스, 쓸만한 하이퍼 바디, 쓸만한 홀리 파운틴, 쓸만한 마녀 모자 자리): 물리·마법 공격력% 각각 `round(7 + 0.6 × 레벨, 2)`. Lv.1 = 7.6, Lv.30 = 25. 10개 모두 Lv.30이면 250%.

### 1.9 솔 야누스와 제네시스 무기

- 솔 야누스(HEXA 공용 코어, 앵커 `function qa(a){`): `skill_name`이 "솔 야누스"로 시작하는 HEXA 스킬의 `slot_level` L에 대해 최종 대미지 `0.5×L + (L≥10이면 3) + (L≥20이면 5) + (L≥30이면 7)`. Lv.10 = 8, Lv.20 = 18, Lv.25 = 20.5, Lv.30 = 30.

## 3. 전투력

앵커 `.3*(1+l("보스 공격력"))` (pretty L1303), `Math.pow(a.max/1e8,.2)` (pretty L1312), `function fn(a,o){` (pretty L3434).

```
전투력 = floor( A × (P + 0.3 × (1 + B)) × (1 + D) × (1.2 + C) × (1 + F) × (M / 100,000,000)^0.2 )
```

| 기호 | 뜻 |
|---|---|
| A | 직업 계열 깡공(출처 합 + 레벨 기본 공격력) |
| P | 직업 계열 공격력% / 100 |
| B | 보스 공격력 / 100 |
| D | 직업 계열 대미지 / 100 |
| C | 치명타 피해 / 100 |
| F | 최종 대미지 / 100 |
| M | 최대 대미지 |

- 발췌: `base:l(`${i} 공격력%`)+.3*(1+l("보스 공격력")),dmg:1+l(`${i} 대미지`),crit:1.2+l("치명타 피해")`
- 방어율 무시와 치명타 확률은 공식에 없다. 보스 공격력은 0.3 기본항에만 곱해져서 공격력% 1%p 대비 가치가 0.3배다.
- **공식 전투력과의 관계**: API 능력치의 "전투력"은 `combatPowerApi`로 보관만 하고 능력치 카드 아래에 "넥슨 API 표기 전투력"으로 작게 보여 준다(앵커 `넥슨 API 표기 전투력`). 보정 계수나 비교 로직은 없다. 이전 조사에서 디올의 API 값(6,106,152)이 계산값과 10배 넘게 달랐고, 우리 고정 데이터에서도 캐릭터마다 비율이 0.6~13배로 들쭉날쭉했다. 그대로 비교 기준으로 쓰기 어렵다.
- 화면의 기본 전투력은 "보스 프리셋", 곧 장비·하이퍼·링크·쥬얼·기계 심장·유니온 스탯 프리셋 조합 전체를 계산해 가장 높은 조합이다(이전 조사: 디올 324개 조합).
- 유니온 공격대원 효과를 못 읽었거나 유니온 스탯이 비면 전투력을 "불완전"으로 표시한다.

## 4. 스탯 환산, 보스 방어율, 보스 입장 조건

### 4.1 스탯 환산(전투력 기준)

앵커 `function K1(a,o,i,l){` (pretty L3547), `function od(a,o,i,l=null){`, `var Q1=[{key:"atk"`.

- 화면 문구는 "게임 전투력 공식으로 계산했어요 · 실제 보스 대미지와는 달라요"다. 3장의 공식을 그대로 쓴다.
- 한 칸 단위: % 스탯 1%p, 깡공 100, 최대 대미지 1,000만.
- 전투력을 l배로 만드는 각 스탯 양(g = l − 1, base = P + 0.3(1+B)):

| 스탯 | 필요량 | 최종 대미지 1%p 상당량(%p, 합계는 % 단위) |
|---|---|---|
| 깡공 | A × g | A / (100 + F) |
| 공격력% | 100 × base × g | (P + 30 + 0.3B) / (100 + F) |
| 보스 공격력 | 100 × base × g / 0.3 | (P + 30 + 0.3B) / (0.3 × (100 + F)) |
| 대미지 | 100 × (1 + D) × g | (100 + D) / (100 + F) |
| 치명타 피해 | 100 × (1.2 + C) × g | (120 + C) / (100 + F) |
| 최종 대미지 | 100 × (1 + F) × g | 1 |
| 최대 대미지 | M × (l^5 − 1) | M × ((1 + 1/(100+F))^5 − 1) |

- 여러 줄을 한꺼번에 넣으면 전체 상승, 줄별 단독 상승, "다른 줄과 함께일 때 이 줄의 몫"을 함께 보여 준다.
- 방어율 무시는 전투력 모드에서 고를 수 없다. 방무 합성: 더할 때 `1 − (1 − a)(1 − o)`, 뺄 때 `(1 − a)/(1 − o)`, 교체(from → to)는 `(1 − to)/(1 − from)`을 곱한다.
- 예상딜(실전딜) 모드는 서버 계산이라 공식이 JS에 없다. 클라이언트가 보내는 값: 스탯(깡공에 +200), 방무 그룹 목록, 보스·포스, HEXA 스킬 레벨, V 특수 코어, 버프 아이템(보스 연습모드 표 25종), 피버(일반 공% 25·치피 25, 맥스 공% 50·치피 50). 계산 기준은 이전 조사대로 보스 10분 딜, 맥스 피버, 버프 7종이다.

## 8. 찾지 못한 것

- 예상딜(실전딜) 공식: 서버에서 계산해 JS에 없다. 클라이언트가 보내는 입력 형식만 확인했다.
- 공식 전투력과 계산 전투력을 잇는 계수: 없다. 공식 값은 표시만 한다.
- 직업 패시브의 만렙 외 레벨 수치: 없다. 15개 직업(다크나이트, 소울마스터, 아란 등)은 직업별 표 없이 추정 기본값이다.
- 직업 계열 공용 코어 외의 직업 코어(V) 스탯: 없다. 직업별 `vcores` 칸은 비어 있다.
- 그란드 심볼 표, 어센틱 심볼 레벨별 실측표: 없다(만렙값 비례 계산).
- 규칙별 게임 패치 날짜·버전: 행 단위로 "2026-09" 같은 표기만 있다. 7/9 V매트릭스 개편이나 7/30 장비 개편을 가리키는 표기는 없다.
- 레이븐혼·라이온하트·팔콘윙·드래곤테일·샤크투스 세트의 스타포스 옵션: 이 사이트 표에 없다(우리 표에만 있음).
- 캐릭터 개인 어빌리티: 다루지 않는다고 스스로 적었다.

`docs/research/rules/`의 JSON 파일은 모두 `sites.maplemtool`과 `sites.maplemworlds` 아래에 항목을 두고, 항목마다 `site`, `file`, `anchor`(번들은 `prettyLine` 포함)를 단다. 우리 현재 값은 필요한 파일에 `ours`로 붙였다.
