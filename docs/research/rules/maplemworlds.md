# maplemworlds.kr 공개 JS로 본 스탯·전투력 규칙

- 작성일: 2026-10-28
- 대상: maplemworlds.kr이 브라우저에 내려주는 공개 JS 번들(빌드 표시 2026-10-28 01:55:44 UTC = 10:55 KST)
- 목적: 그 사이트가 캐릭터 스탯 합산, 최대 대미지, 전투력, 스탯 환산, HEXA·심볼·해방 계산에 쓰는 규칙과 상수를 우리 말과 표로 정리한다. 우리 사이트(maplem.co.kr) 스탯 계산을 다시 맞출 때 대조 자료로 쓴다.
- 원칙: 값과 규칙만 옮겼다. 코드는 근거 추적용으로 한두 줄만 발췌하고, 위치는 원본 파일명과 검색용 앵커 문자열로 적었다. 앵커는 원본 파일에서 정확히 한 번만 나오는 것을 스크립트로 확인했다. "pretty L번호"는 js-beautify로 정리한 사본의 줄 번호다.
- 이 문서의 수치는 그 사이트가 쓰는 값이다. 게임 공식 값인지는 따로 확인하지 않았다(확인된 경우만 따로 적음).

### 0.2 수집·분석 방법

- Headless Chromium으로 홈과 캐릭터 화면(스카니아/디올)을 한 번씩 열고, 그때 받은 JS만 저장했다. maplemworlds.kr로 가는 GET 외 요청과 광고·분석 요청은 브라우저에서 막았고, 그들의 API 응답은 저장하지 않았다.
- 본체가 지연 로딩하는 청크 5개는 같은 파일을 1.5초 간격으로 한 번씩 GET 했다.
- js-beautify로 정리한 뒤 한글 라벨로 로직을 따라갔다. 상수 표는 acorn 파서로 리터럴만 읽어 냈다(코드 실행 없음).

### 0.3 핵심 요약

1. 최대 대미지는 "스킬 > 패시브" 고정값 **4억**에서 출발해 출처별 값을 단순 합한다. 1억 기본값은 없고, 1억은 전투력 공식의 기준점으로만 쓴다.
2. 전투력: `깡공 × (공% + 0.3×(1+보공)) × (1+대미지) × (1.2+치피) × (1+최종) × (최대 대미지/1억)^0.2`. 방어율 무시는 들어가지 않는다.
3. 직업 패시브는 직업 구분 없는 고정값 하나다(공격력% 300, 대미지 60, 보공 10, 치피 30, 최종 10, 최대 대미지 4억).
4. V매트릭스는 합산하지 않는다.
5. 방어율 무시는 항목마다 곱연산한다. 아케인 세트효과와 아케인 스타포스 옵션의 방무만 먼저 서로 더한다.
6. 장비 기본 옵션 값에 추가 옵션이 이미 들어 있다고 보고, 같은 스탯의 추가 옵션 값을 기본 옵션에서 뺀다.
7. 아케인·앱솔·칠흑 세트효과와 아케인·앱솔 스타포스 옵션은 자체 표로 계산한다. API 세트효과는 "차원 균열의 반지 세트"와 마스터 라벨 세트만 반영한다.
8. 아케인 스타포스 옵션의 최대 대미지가 우리 표의 정확히 1.5배다(아래 1.4).

## 1. 주요 스탯 합산 규칙

캐릭터 상세의 "스탯" 탭, 전투력, 보스 세팅이 모두 한 함수(`xf`)의 결과를 쓴다.

- 출처: `index-5Pk4vujo.js`, 앵커 `function xf(A,e,t,n,l,r,i,o,f){` (pretty L15848)

### 1.1 대상 스탯과 합계 방식

- 키 11개: 마법 공격력, 물리 공격력, 마법 공격력%, 물리 공격력%, 마법 대미지, 물리 대미지, 보스 공격력, 치명타 피해, 최대 대미지, 최종 대미지, 방어율 무시(앵커 `ti=["마법 공격력","물리 공격력"`).
- 물리·마법 두 벌을 모두 쌓고, 화면에는 합이 큰 쪽만 보여 준다. 깡공의 큰 쪽이 공격력% 쪽도 정한다. 대미지는 따로 큰 쪽을 고른다.
- 방어율 무시를 뺀 나머지는 단순 합이다. 방어율 무시는 항목별 곱연산이다.
  - 발췌: `100*(1-e.reduce((t,n)=>t*(1-n.value/100),1))`
  - 아케인 세트효과의 방무와 아케인 스타포스 옵션의 방무는 먼저 더해서 "아케인셰이드 세트 (합산)" 한 항목으로 만든 다음 곱연산에 들어간다(앵커 `label:"아케인셰이드 세트 (합산)"`).
- 각 항목은 분류를 단다: 장비, 스킬, 성장, 콘텐츠. 상세 화면은 이 네 분류로 기여도를 묶어 보여 준다.

문구 파싱 공통 규칙(앵커 `replace(/보스 몬스터 공격 시 대미지/g,"보스 공격력")`):
- "데미지"는 "대미지"로, "크리티컬 대미지"는 "치명타 피해"로, "보스 몬스터 공격 시 대미지"는 "보스 공격력"으로 바꾼다.
- "물리 공격력 및 마법 공격력 X", "물리 대미지 / 마법 대미지 X", "물리/마법 공격력 X"처럼 묶인 문구는 물리·마법 양쪽에 X를 각각 넣는다.
- 공격력 뒤 숫자에 %가 붙으면 공격력% 키로 보낸다. 다른 스탯은 %와 무관하게 숫자만 읽는다.
- 숫자는 쉼표·기호만 지우고 읽는다. "만" 단위는 해석하지 않는다(2장 참고).
- 키 이름이 긴 것부터 맞춘다. "치명타 피해 감소"처럼 스탯 이름 뒤에 숫자가 바로 오지 않으면 잡히지 않는다.

### 1.3 장비 옵션(기본·추가·잠재·에디셔널)

앵커 `f8=[["item_basic_option","기본 옵션"]` (pretty L15578)

- 네 묶음(기본 옵션, 추가 옵션, 잠재, 에디셔널 잠재)의 각 줄을 스탯 키로 바꿔 더한다. 이름에 스탯명이 포함되면 매칭하고, 공격력 줄은 값에 %가 있으면 공격력% 키다.
- **기본 옵션 보정**: 기본 옵션 줄 값에서 같은 키의 추가 옵션 합을 빼고(0 미만이면 0) 더한다. 기본 옵션 값이 이미 추가 옵션을 포함한다고 보는 것이다. 추가 옵션은 따로 그대로 더하므로 합계는 기본 옵션 값과 같아진다. 템환산(4.5) 쪽은 같은 이유로 "같은 키가 기본 옵션에 없을 때만 추가 옵션을 더한다".
  - 참고: 우리가 보관한 넥슨 API 샘플(`research-nexon-api/raw/character-item-equipment.json`)의 "루즈 컨트롤 머신 마크"는 기본 옵션 최종 대미지 11.50%, 추가 옵션 최종 대미지 6.50%로 나온다. 이 사이트 규칙대로면 최종 대미지 기여는 11.5%이고, 두 값을 모두 더하면 18%가 된다.
- **무기 마스터리 보너스**: 무기의 추가 옵션 깡공(% 없는 물리/마법 공격력)이 그 추가옵션 등급의 불꽃 최대치보다 크면, 기본 옵션 기여에 보너스를 더한다(앵커 `value:1931,bonus:1200`).

| 추가옵션 등급 | 판정 기준(초과) | 더하는 값 |
|---|---|---|
| 에픽(2) | 1,352 | +900 |
| 유니크(3) | 1,931 | +1,200 |

  - 1,352와 1,931은 그 사이트 불꽃 표의 200제 무기 깡공 최댓값(에픽 1,127~1,352, 유니크 1,609~1,931)이고, 900·1,200은 마스터리 2포인트분(에픽 450, 유니크 600 × 2)과 같다.
- 기계 심장(안드로이드 하트)은 장비 한 칸처럼 넣는다. 추가 옵션·잠재·에디셔널을 모두 읽고, 잠재·에디는 "성장"으로 분류한다. 물리·마법 구분 없이 모든 키를 받는다.
- 장비 목록에는 칭호·훈장·뱃지·포켓 같은 칸도 들어가므로 칭호 효과는 API 장비 옵션으로 반영된다.

### 1.4 아이템 세트 효과와 스타포스 세트 옵션

세트 판정(앵커 `g=["루즈 컨트롤","마력이 깃든"`, `for(const R of["아케인","앱솔"])`):
- 아이템 이름에 "아케인셰이드"가 있으면 아케인, "앱솔랩스"면 앱솔, 다음 이름 중 하나가 있으면 칠흑 세트 1개로 센다: 루즈 컨트롤, 마력이 깃든, 몽환의 벨트, 저주받은 청의, 저주받은 적의, 거대한 공포, 고통의 근원, 커맨더 포스 이어링, 창세의 뱃지, 미트라의 분노, 감시자의 눈.
- 세트별로 스타포스를 합한다. 한벌옷은 2배다.
- 무기가 제네시스면 럭키 아이템으로 본다. 아케인·앱솔 가운데 이미 3세트 이상인 세트마다 개수 +1, 스타포스 합에 무기 스타포스를 더한다.

### 1.7 HEXA 스탯과 솔 야누스

- HEXA 스탯: 활성(`activate_flag`=1) 스탯 코어의 메인·부가 스탯 문구를 파싱한다. API 문구에 수치가 들어 있으므로(예: "최대 대미지 400,000,000 증가") 실제로는 API 값을 쓴다. 문구에 숫자가 없을 때만 "레벨 × 가중치(메인 1, 부가 0.75)"를 대신 쓴다(앵커 `["sub_1_stat","sub_1_stat_level",.75]`). 스탯 페이지는 화면에서 고른 페이지를 쓴다.
- 솔 야누스(HEXA 공용 코어): Lv.L(0~30)일 때 최종 대미지 = 0.5×L + (L≥10이면 3) + (L≥20이면 5) + (L≥30이면 7). Lv.10 = 8%, Lv.20 = 18%, Lv.30 = 30%(앵커 `label:"솔 야누스"`).
- HEXA 스탯 값표는 5.2에 있다(가이드 화면용).

### 1.9 API 밖 수동 입력 항목

수동 입력 목록(앵커 `I8=[j8,y8,E8,C8,X8,V8,U8,h8]`): 스타코러스, 컨스텔라 코어, 성흔, 축복, 펫, 유니온 챔피언, 명예 배지, 몬스터 컬렉션.
- **기본값은 모두 비어 있다(기여 0).** 사용자가 고른 값만 더한다. 인증 캐릭터는 서버 저장값, 그 외는 브라우저 저장값을 쓴다.
- 컨스텔라 코어는 목록에 있지만 합산 대상에서 빠져 있다(앵커 `vl=I8.filter(A=>A.id!=="constella")`).

## 3. 전투력

계산 전투력(앵커 `const o=e+.3*(1+t),f=1+n,m=1.2+l,d=1+r,c=Math.pow(i/i8,.2)`, pretty L15422):

```
전투력 = round( A × (P + 0.3 × (1 + B)) × (1 + D) × (1.2 + C) × (1 + F) × (M / 100,000,000)^0.2 )
```

| 기호 | 뜻 |
|---|---|
| A | max(마법 공격력 합, 물리 공격력 합, 1). 레벨 기본 공격력을 포함한 깡공 |
| P | max(마법 공격력%, 물리 공격력%) / 100 |
| B | 보스 공격력 / 100 |
| D | max(마법 대미지, 물리 대미지) / 100 |
| C | 치명타 피해 / 100 |
| F | 최종 대미지 / 100 |
| M | max(최대 대미지 합, 1) |

- 방어율 무시와 치명타 확률은 공식에 없다.
- 보스 공격력은 0.3 기본항에만 곱해진다. 공격력% 1%p와 보스 공격력 1%p의 가치 비는 1 : 0.3이다.
- 공식 전투력(API 능력치의 "전투력")은 읽지도, 보정하지도 않는다. 화면의 "현재 측정 전투력"은 현재 장비로 이 공식을 계산한 값이고, 장비 체험 중에는 "체험 전투력"과 차이를 보여 준다.
- 보스 세팅(앵커 `androidPresetNo:it,hyperPresetNo:ot`): 장비 프리셋 1~3 × 안드로이드 하트 프리셋 1~3 × 하이퍼 프리셋 × 쥬얼 페이지 × 링크 프리셋 × 유니온 스탯 프리셋을 모두 계산해 전투력이 가장 높은 조합을 고른다. 엘프의 축복이 경험치 문구로 들어간 링크 프리셋(사냥용)은 후보에서 뺀다. 이 탐색에는 HEXA 스탯 페이지를 넘기지 않아서, API에서 활성(`activate_flag`=1)으로 표시된 스탯 코어를 쓴다.
- 기본정보의 "최고 전투력"은 현재 장비 값과 장비 프리셋 1~3 각각의 값 가운데 최댓값이다. 보스 입장 표는 서버에 저장된 최고 기록(`characterRecord.combat_power`)과 비교한다.

## 4. 스탯 환산, 보스 방어율, 보스 입장 조건

### 4.1 스탯 효율: 전투력 모드

- 3장의 전투력 공식을 그대로 쓴다(앵커 `U6=[{key:"finalDmg"`). 선택한 스탯을 증가량만큼 올렸을 때의 전투력 상승분을 기준으로, 같은 상승을 내려면 다른 스탯이 얼마나 필요한지 보여 준다.
- 계산: 필요량 = 그 스탯 기준 증가량 × (선택 스탯 상승분 ÷ 그 스탯 기준 증가량의 상승분). 최대 대미지만 정확식 `M × ((1+g)^5 − 1)`을 쓴다(g = 선택 스탯의 상승률).
- 기준 증가량: 최종 대미지·치명타 피해·공격력%·대미지·보스 공격력 1%p, 깡공 100, 최대 대미지 1,000만. 방어율 무시는 이 모드에서 고를 수 없다.
- 공식을 풀면 최종 대미지 1%p와 같은 값은 다음과 같다(퍼센트 단위, P·B·D·C·F는 % 합계).

| 스탯 | 최종 대미지 1%p 상당량 |
|---|---|
| 공격력% | (P + 30 + 0.3B) / (100 + F) |
| 보스 공격력 | (P + 30 + 0.3B) / (0.3 × (100 + F)) |
| 대미지 | (100 + D) / (100 + F) |
| 치명타 피해 | (120 + C) / (100 + F) |
| 깡공 | A / (100 + F) |
| 최대 대미지 | M × ((1 + 1/(100+F))^5 − 1) |

- 검증: 이전 조사(`docs/research/competitor-maplemworlds.md` 5장)에서 화면에 나온 "최종 대미지 1% = 마법 공격력 1.86%"는 그 캐릭터 값(마공% 503, 보공 506.58, 최종 267.9)을 넣으면 1.862로 맞는다.

### 4.2 스탯 효율: 대미지 효율 모드와 도핑

- 공식(앵커 `S6=400`, pretty L41590):

```
대미지 = A × (P + 4 × (1 + B)) × (1 + D) × (1.2 + C) × (1 + F) × (1 − 보스방어율 × (1 − IED))
```

  - 여기서 4는 상수 400%(`S6`)를 100으로 나눈 값이다. 보스 공격력이 이 기본항에 곱해지므로 전투력 모드보다 보스 공격력 가치가 훨씬 크다.
  - 방무를 t%p 올릴 때는 곱연산: IED' = 1 − (1 − IED)(1 − t/100).
  - 최대 대미지는 이 공식에 없어서 이 모드에서 고를 수 없다. 기준 증가량은 깡공 300, 나머지 1%p.
- 도핑(앵커 `u0=[{key:"five",name:"5종"`): 이 모드에서만 체크한 항목을 더한다. 기본 체크는 5종과 맥피다.

| 도핑 | 공격력% | 보공 | 대미지 | 치피 |
|---|---|---|---|---|
| 5종 | 30 | 30 | 30 | 30 |
| 맥피 | 50 | - | - | 50 |
| 일피 | 25 | - | - | 25 |
| 탕탕 | - | 20 | 20 | - |
| 보킬 | - | 50 | - | - |
| 고보킬 | - | 100 | - | - |
| MVP | 30 | - | - | - |
| 길스 | - | - | 10 | - |
| 유니온 | 30 | - | - | - |
| 요리 | - | 10 | - | 5 |

- 검증: 같은 캐릭터에 기본 도핑(5종+맥피)을 넣으면 최종 1% = 마법 공격력 8.506%로, 화면 값 8.51%와 맞는다.
- 독립 화면 기본 입력(앵커 `B6={rawAtt:12e4`): 깡공 120,000, 공격력% 500, 대미지 760, 보공 430, 치피 415, 최종 297, 방무 82, 보스 방어율 77.89, 최대 대미지 1억. 캐릭터 상세에서 열면 캐릭터 합산값을 쓰고 보스 방어율만 77.89로 시작한다.

- 직업별 패시브 스킬 수치: 없다. 모든 직업에 같은 고정값(1.5)을 쓴다.
- 심볼 레벨별 스탯 표, 하이퍼 스탯 레벨별 표, 유니온 레벨·공격대 효과 표: 없다. 모두 API 문구를 파싱한다.
- V매트릭스 코어 효과 규칙: 없다(합산 안 함).
- 공식 전투력과 계산 전투력의 관계(보정 계수 등): 코드에 없다. 공식 전투력 값을 읽지 않는다.
- 스타포스 단계별 장비 스탯 표: 클라이언트에 없다. 장비 체험 때 서버에서 받는다.
- 보스 입장 레벨 조건: 없다(입장 전투력만 있음).
- 보스 방어율을 0.9736배로 줄인 근거, 대미지 효율 모드의 상수 400%의 근거: 코드에 설명이 없다.
- 축복 이외 수동 항목의 서버 저장 형식과 인증 캐릭터 저장값: 로그인이 필요해 보지 않았다.

## 9. maplemtool과의 차이

전체 대조표는 `maplemtool.md` 7장에 있다. 우리 코드와 비교한 결과는 `diff-vs-ours.md`에 있다. 요점만 적는다.

- 같은 것: 최대 대미지 기본 4억, 전투력 공식(이쪽은 `round`, maplemtool은 `floor`), 솔 야누스 공식, 제네시스 무기 최종 +10, 본인 링크(70/120/260 → Lv.1/2/3), 장비 기본 옵션에서 같은 키의 추가 옵션을 빼는 규칙, 문장·쥬얼 합산, 길드 공용 스킬과 지하수로·전장 전용 어빌리티 제외, 아케인 스타포스 최대 대미지(우리 표의 1.5배), HEXA 오리진·마스터리·강화 비용, HEXA 스탯 값(메인 Lv.6 최대 대미지만 이쪽 가이드가 3억 2,000만으로 다름), 수동 입력 값표(성흔·배지·챔피언·몬스터 컬렉션), 기본값 0.
- 다른 것:
  - 패시브: 이쪽은 전 직업 고정값(공격력% 300, 대미지 60 등)이고 V매트릭스를 따로 계산하지 않는다. maplemtool은 직업별 표(공격력% 50, 대미지 35)에 V 코어(7+0.6L)와 직업 계열 코어(16+0.3L)를 API 레벨로 더한다. V 코어를 다 키운 캐릭터면 결과가 같다.
  - 세트: 이쪽은 아케인·앱솔·칠흑만 자체 표로 계산하고 다른 API 세트 효과(펜살리르·군단장 등)를 넣지 않는다. maplemtool은 API 세트 효과를 쓰고 스타포스 옵션도 7개 세트로 계산하며 빌림 규칙이 있다.
  - 앱솔 스타포스 70구간 최대 대미지: 이쪽 500만, maplemtool 550만(공식 스크린샷은 550만).
  - 방어율 무시: 둘 다 곱연산이지만 maplemtool은 아이템 단위로 먼저 더한다.
  - 보스 방어율: 이쪽은 0.9736배로 줄인 값(77.89 등), maplemtool은 30~80 그대로. 보스 입장: maplemtool은 레벨 조건도 있고 진 힐라 하드 입장 전투력이 28,807,000(이쪽 32,267,000).
  - HEXA 공용 코어 비용: 이쪽 캐릭터 화면 표의 네 칸(24→25, 27→28, 28→29, 29→30)이 가이드·계산기·maplemtool과 다르다.
  - 길드 어빌리티 계산기: 7·8차의 이름과 효과가 서로 바뀌어 있다. API 문구와 maplemtool은 욕망의 끝·극한의 힘이 최종 대미지, 최강 전사의 덕목·한계 돌파가 최대 대미지다.
  - 스탯 환산: 이쪽만 대미지 효율 모드(상수 400%, 도핑)가 있다. maplemtool의 예상딜은 서버 계산이다.

## 부록. 기계 판독용 추출 파일

스크립트로 원본 번들에서 뽑은 상수표다. 항목마다 `site`, `file`, `anchor`, `prettyLine`을 달았다. 저장소의 `docs/research/rules/<파일>.json` 안 `sites.maplemworlds` 아래에 maplemtool 값과 나란히 합쳐 두었다(`blessing.json`의 maplemworlds 축복 전체 표 포함).
