- 작성일: 2026-10-28 · 관찰 시각: 14:48~15:54 KST
- 목적: maplem.co.kr(메이플M 플러스) 전면 개편을 위한 경쟁 사이트 기능 인벤토리
- 원칙: 공개 화면에서 본 기능과 사용 흐름만 우리 말로 정리했다. 그 사이트의 코드·문구·그래픽·레이아웃은 옮기지 않았다. 메뉴 이름처럼 기능을 가리키는 데 꼭 필요한 짧은 명칭만 따옴표로 적었다.

## 1. 사이트 개요

- 성격: "메이플M 전투력 계산기"를 내건 비공식 도구 사이트다. 메인 가치는 넥슨 Open API 데이터와 사용자가 직접 넣는 값을 합쳐 게임 전투력을 다시 계산하고, 무엇을 키우면 얼마나 오르는지 보여 주는 것이다.
- 상단 메뉴는 홈, 랭킹, 내 캐릭터 세 개뿐이다. 나머지 기능은 캐릭터 화면 안에 들어 있다. 캐릭터 화면은 하단 탭 6개(스펙·장비·캐릭터·육성·수집·길드)와 각 탭의 왼쪽 하위 메뉴, 버튼으로 여는 모달, 전체 화면 성장 시뮬레이터로 이루어져 있다.
- URL 체계(딥링크):
  - 캐릭터: `/?name=<이름>&world=<월드>`
  - 하위 화면은 해시로 연다: `#stat:exp`, `#stat:eff`, `#stat:liberation`, `#stat:journal`, `#char:hexa`, `#char:ascent`, `#char:serion`, `#char:skill`, `#raise:link`, `#raise:union`, `#gear:sanct`, `#manual:stella`, `#card`
  - 성장 시뮬레이터: `&growth=<영역>`(equipment, symbol, jewel, stigma, pet, hyper, vmatrix, hexaSkill, hexa, stella, serion, union, unionStat, unionChampion, link, monsterCollection, badge, guild, recommend, forgeRec, boss, blessing)
  - 랭킹: `/?view=rank&type=level|item|jobchange`, `&world=`, `&q=`, 아이템은 `&name=<아이템명>`
  - 건의함: `/?view=board`, `&tab=answered`, `&post=<번호>`
  - 개인정보 처리방침: `/?view=privacy`, 이전 판 `&v=YYYYMMDD`
- 구조 관찰(화면을 띄울 때 브라우저가 보낸 요청과 공개 HTML에서 확인):
  - Cloudflare 위에서 돌아가는 SPA다. 저장소는 Cloudflare D1이라고 처리방침에 적혀 있다.
  - HTML 머리에 게임 데이터 테이블 38개의 파일 이름이 공개돼 있다(부록 A). 이 테이블을 미리 받아 전투력과 비용 계산을 브라우저에서 즉시 하는 구조로 보인다. 숫자를 바꾸면 결과가 바로 바뀐다.
  - '예상딜/실전딜'은 서버 계산 요청을 따로 보내 받아온다. 계산 서버 연결에 실패하면 실패 문구가 뜬다.
  - 캐릭터 조회, 경험치 기록, 레벨 순위, 같은 유니온 캐릭터, 랭킹 목록·검색, 넥슨 공지, 건의함, 로그인 상태를 각각 자체 API로 불러온다.
  - 짧은 링크와 미리보기 이미지 저장, 기능 사용 횟수 집계는 쓰기 요청으로 따로 보낸다.
- 고지: 모든 화면 하단에 넥슨 Open API 데이터 기반이라는 표시, 넥슨 저작권, "넥슨과 무관한 비공식 서비스"라는 문구, 건의함과 카카오톡 오픈채팅(문의·오류 제보) 링크, 개인정보 처리방침이 있다.

## 3. 기능별 상세

표기: 경로 / 설명 / 입력 / 결과 / 화면 핵심 요소(추상) / 필요 API(추정, 우리 엔드포인트 이름 기준) / 추가 데이터·계산(공개 범위와 관찰 사례) / 난이도 / 우리 유사 기능 / 우선순위 / 확인 상태와 근거

### 3.1 캐릭터 분석

#### F01. 캐릭터 검색
- 경로: 모든 화면 상단의 검색 바(월드 선택, 이름, 조회 버튼). 조회하면 `/?name=…&world=…`로 이동한다.
- 설명: 월드를 고르고 이름으로 찾는다. 고른 월드에 없으면 다른 월드까지 자동으로 찾아본다. 그래도 없으면 '어느 월드에서도 못 찾았다'는 안내가 뜬다. 조회 직후 몇 초 동안은 조회·갱신 버튼에 카운트다운이 붙어 연타를 막는다(관찰 5초). 자동완성은 없다.
- 입력: 월드 7개(스카니아·루나·엘리시움·크로아·제니스·유니온·아케인. 챌린저스는 없음), 캐릭터명
- 결과: 캐릭터 화면. 브라우저에 '최근 본 캐릭터'가 쌓인다.
- 화면: 엠블럼이 붙은 월드 드롭다운과 넓은 입력창. 모바일 캐릭터 화면에서는 검색 아이콘으로 접힌다.
- 필요 API: id, character/basic
- 추가 데이터: 없음
- 난이도 하 · 우리: 있음(챌린저스까지 지원) · 우선순위 P0. 전 월드 자동 재탐색과 연타 방지 안내를 우리 검색에 넣을 만하다.
- 확인 상태: 확인 완료. 3명을 조회했고, 없는 이름을 조회해 안내 문구와 전 월드 탐색 요청을 관찰했다.

#### F02. 캐릭터 헤더 + 계산 전투력 + 데이터 기준 시각
- 경로: 캐릭터 화면 상단
- 설명: 이름·레벨·직업·월드·길드 아래에 사이트가 직접 계산한 전투력을 가장 크게 보여 준다. 기본값은 '보스 프리셋', 곧 최고 전투력 조합(F04) 기준이다. 옆에는 '빈칸 n개 남음' 배지가 붙는다(F21). 오른쪽에는 데이터 기준 시각이 있고, 펼치면 정확한 갱신 시각(KST)이 나온다. 툴팁에는 '24시간 이내 저장 데이터는 자동 사용'이라고 적혀 있다. 새로 불러오기 버튼에는 쿨다운이 있다. 장비창 옆 말풍선에 레벨 순위(월드/전체)가 뜨고, 말풍선 설정에서 전투력·레벨·유니온·무릉도장·업적 순위 가운데 무엇을 보일지 고를 수 있다. 넥슨 API가 주는 전투력 값은 능력치 탭 아래에 작게 따로 적어 둔다.
- 입력: 조회 데이터 전부 + 수동 입력값
- 결과(관찰): 디올 867,888,292 / 성령 768,319,696 / 캐슬 340,814,773(모두 보스 프리셋 기준, 빈칸 8개 미입력)
- 화면: 큰 숫자 하나, 보조 배지, 기준 시각, 액션 버튼 줄(프리셋·관심·비교·새로 불러오기·링크 공유)
- 필요 API: character/basic, stat, item-equipment, symbol, set-effect, jewel, hyper-stat, link-skill, vmatrix, hexamatrix-skill, hexamatrix-stat, user/union, user/union-raider, guild/basic, pet-equipment, ranking/level
- 추가 데이터·계산: 화면에는 '게임 전투력 공식으로 계산'했다는 말만 있고 공식은 공개하지 않는다. 직업별 스킬 패시브, 링크·유니온·길드 효과, 세트 효과 같은 게임 데이터 테이블이 필요하다(부록 A).
  - 관찰된 값 불일치: 같은 캐릭터에 전투력 값이 여러 개 있다.
    - 디올: 계산(보스 프리셋) 867,888,292 / 조회 당시 착용 조합으로 계산 64,096,437 / 랭킹 '최근 30일 최고' 12억 6,589만 / API 표기 6,106,152
    - 성령: 계산 768,319,696 / 랭킹 11억 8,930만 / API 표기 203,403,518
    - 캐슬: 계산 340,814,773 / 랭킹 5억 7,640만
  - 사이트는 빈칸 8종을 넣으면 전투력이 맞게 나온다고만 안내한다. 스텔라코드 같은 미입력분이 차이의 큰 부분으로 보이지만 검증하지는 못했다.
  - API의 전투력 필드는 캐릭터마다 계산값과의 비율이 크게 달라서 그대로 비교에 쓰기 어렵다. 우리 화면에 API 전투력을 노출하고 있다면 다시 검증해야 한다.
- 난이도 상 · 우리: 부분(기본정보·스탯) · 우선순위 P0. 모든 계산기가 이 엔진 위에 선다.
- 확인 상태: 확인 완료(데스크톱·모바일, 3명)

#### F03. 장비창·장비 프리셋·외형 탭·요약 배지
- 경로: 캐릭터 화면 왼쪽 카드
- 설명:
  - 인게임 장비창과 비슷한 배치로 23부위 아이콘과 캐릭터 이미지를 보여 준다. 아이콘에는 잠재·에디 등급 글자와 마스터리 표시가 붙는다.
  - 장비 프리셋 1~3을 고를 수 있고, 최고 조합 토글(F04)이 있다.
  - '외형' 탭은 헤어·성형·피부와 염색·렌즈 혼합 비율을 보여 준다.
  - 하단 배지 4개: 스타포스 합계, 아케인포스(전부 MAX인지), 어센틱포스(MAX 개수 n/7), 유니온 레벨·등급
  - 캐릭터 이미지는 표정을 바꿀 수 있고, 길게 누르면 다른 모습으로 바뀐다(재미 요소).
- 필요 API: item-equipment(프리셋 포함), beauty-equipment, symbol, user/union, character/basic(이미지)
- 추가: 표정·자세를 바꾸려면 넥슨 캐릭터 이미지 URL이 파라미터를 지원해야 하는데, 지원 여부는 확인이 필요하다.
- 난이도 중 · 우리: 부분(장비·캐시·안드로이드·펫·뷰티. 프리셋 전환 여부는 우리 쪽 확인 필요) · 우선순위 P1
- 확인 상태: 확인 완료

#### F05. 스펙 요약 카드
- 경로: 캐릭터 화면 오른쪽 카드
- 설명: 잠재 합(물댐+보공 등)·에디 합·방어율 무시·최대 대미지 4지표를 보여 준다. HEXA 코어 아이콘·레벨과 HEXA 스탯 요약, 솔 에르다 조각 사용률(%), 스텔라코드 미니맵(입력 여부)도 있다. 카드 하단에 사이트명이 찍혀 있어 캡처 공유를 염두에 둔 구성으로 보인다.
- 필요 API: item-equipment, stat, hexamatrix-skill, hexamatrix-stat
- 추가: HEXA 누적 조각 비용 테이블(사용률 계산용). 스텔라코드는 수동 입력이다.
- 난이도 하 · 우리: 부분 · 우선순위 P1
- 확인 상태: 확인 완료

#### F06. 능력치 상세·기타 능력치
- 경로: 하단 '스펙' 탭 > 능력치 / 기타 능력치
- 설명:
  - 공격 지표 9개(물공, 물공%, 물댐, 보공, 치피, 최대 대미지, 최종 대미지, 방무, 공격숙련도)를 행마다 펼칠 수 있게 보여 준다. 펼침 표시로 보아 출처 분해로 추정된다.
  - 맨 아래에 넥슨 API 전투력을 따로 적는다.
  - 기타 능력치는 경험치·파티 경험치·드롭률·메소 획득량이다. 출처 분해에서 성흔·명예 배지·몬스터 컬렉션은 API가 주지 않아 뺐다고 밝힌다.
- 결과(디올): 물공 156,980 / 물공% 514% / 물댐 907.95% / 보공 551.86% / 치피 609.6% / 최댐 3,278,400,000 / 최종 427.2% / 방무 86.826% / 공격숙련도 68.84% / 경험치 획득량 165%
- 필요 API: stat, hyper-stat, item-equipment, user/union
- 난이도 중 · 우리: 부분(스탯·하이퍼스탯) · 우선순위 P1
- 확인 상태: 일부 확인. 행 펼침(출처 분해)은 자동 조작으로 열지 못했다.

#### F07. 장비 옵션 표
- 경로: 하단 '장비' 탭 > 장비 옵션(+ '잠재·에디' 요약, '기계 심장')
- 설명:
  - 부위마다 한 줄씩 기본옵션·스타포스·잠재(등급+완성도 점수)·에디(완성도)·추가옵션(완성도)·소울/문장을 보여 주고, 열 필터로 골라 볼 수 있다.
  - 완성도 점수: 툴팁에 따르면 해당 등급 최고치 대비 비율이며 전투력 기준이다.
  - 장비 마스터리: 옵션 값 옆에 마스터리 보너스(+4% 등)를 따로 적는다. API가 프리셋 장비의 마스터리를 주지 않아 옵션 값에서 거꾸로 셌다고 툴팁에 밝히고 있다.
  - 하단에서 세트 효과(세트 수, 럭키 아이템 +1, 스타포스 세트)를 풀어 설명한다.
  - '잠재·에디' 요약은 물댐·보공 각각의 잠재와 에디 합계다.
- 결과(디올): 무기 잠재 완성도 97.68, 에디 88.81. 잠재 물댐 201.62% + 에디 256.6% = 458.22%, 보공 115.26% + 176.1% = 291.36%(둘을 합쳐 749.58%)
- 필요 API: item-equipment, set-effect
- 추가: 등급별 옵션 최대값 테이블(완성도), 마스터리 보너스 규칙, 럭키 아이템 규칙
- 난이도 중~상 · 우리: 부분(장비 상세·잠재능력 확률표·아이템 공유 이미지) · 우선순위 P1
- 확인 상태: 확인 완료(툴팁 문구 포함)

#### F09. 쥬얼·펫·기계 심장·빛의 성소 표시
- 경로: '장비' 탭 > 쥬얼 / 펫 / 기계 심장 / 빛의 성소·성흔
- 설명:
  - 쥬얼: 현재 페이지의 5칸 등급·옵션과 세트 효과
  - 펫: 3마리와 세트 효과. 레벨 같은 일부 값은 수동 입력이다.
  - 기계 심장: 프리셋 1~3과 잠재·에디
  - 빛의 성소(축복)·성흔: API가 주지 않아 수동 입력 버튼과 축복 시뮬레이터 링크만 있다.
- 필요 API: jewel, pet-equipment, item-equipment
- 난이도 하 · 우리: 부분(쥬얼·펫) · 우선순위 P2
- 확인 상태: 확인 완료

#### F10. 하이퍼 스탯·V매트릭스·HEXA(점수·조각 사용률)
- 경로: '캐릭터' 탭 > 하이퍼 스탯 / V매트릭스 / HEXA
- 설명:
  - 하이퍼: 프리셋 번호와 스탯별 레벨·효과
  - V매트릭스: 총점과 코어별 점수(직업·공용·특수 필터), 공용 코어의 공격력% 합계(n/250%)
  - HEXA: 매트릭스 점수, 조각 사용량/전체, 코어별 레벨·점수·설명, HEXA 스탯
  - 툴팁에 따르면 V매트릭스 점수는 전투력 공식 밖이다(5장).
- 결과(디올): V매트릭스 5,910만. HEXA 매트릭스 점수 487,663,000, 조각 47,181/47,181(100%). 솔 야누스 Lv.30 146,381,000, 스킬 코어 Lv.30 75,250,000, 강화 코어 Lv.30 36,555,000
- 필요 API: hyper-stat, vmatrix, hexamatrix-skill, hexamatrix-stat
- 추가: 코어 레벨별 점수, HEXA 조각 비용 테이블
- 난이도 중 · 우리: 부분(표시만) · 우선순위 P1
- 확인 상태: 확인 완료

#### F11. 장착 스킬
- 경로: '캐릭터' 탭 > 장착 스킬
- 설명: 스킬 프리셋 묶음(P1~P8)을 보여 주고 인게임 슬롯 배치를 재현한다. 아이콘을 누르면 이름과 소속 묶음이 나온다. '스킬 패시브 상세'에서는 패시브 합계 수치(예: 물공% 300, 최종 50, 치피 30)를 보여 준다. 조회 전용이다.
- 필요 API: skill-equipment
- 추가: 직업별 패시브 테이블(합계 계산용)
- 난이도 중 · 우리: 부분(스킬·링크스킬) · 우선순위 P2
- 확인 상태: 확인 완료

#### F12. 유니온 상세
- 경로: '육성' 탭 > 유니온 / 유니온 챔피언
- 설명: 등급·레벨 총합, MAX 달성도, 등록 가능 공격대원 수를 보여 준다. 유니온 스탯(160/160P)·공격대원 효과·레벨 총합 누적 효과·총합을 공격 스탯과 그 외로 나눈다. 유니온 챔피언은 수동 입력이다.
- 필요 API: user/union, user/union-raider
- 추가: 등급·레벨 총합 효과 테이블
- 난이도 중 · 우리: 있음(유니온·유니온 레이더) · 우선순위 P2
- 확인 상태: 확인 완료

#### F14. 길드 탭
- 경로: '길드' 탭
- 설명: 길드명·레벨·마스터·인원을 보여 준다. 길드 어빌리티는 1~8차의 등급·레벨·효과를 보여 주며, 지하수로·전장 전용 효과를 구분한다. 개인 스킬과 적용 효과 합계도 있다. 별도 길드 검색이나 길드원 목록 화면은 찾지 못했다.
- 필요 API: guild/id, guild/basic(길드 스킬이 응답에 들어 있는지 확인 필요)
- 난이도 하 · 우리: 있음(길드 조회 페이지가 더 넓음) · 우선순위 P3
- 확인 상태: 확인 완료

#### F15. 같은 유니온 캐릭터(부캐 추정)
- 경로: '육성' 탭 > 유니온 하단
- 설명: 같은 월드에서 유니온 지문(등급·레벨·공격대원 효과·유니온 스탯 프리셋 요약값, 처리방침 표현 기준)이 같은 캐릭터를 '부캐일 수 있음'으로 보여 준다. 디올 화면에서는 3명이 나왔다.

#### F22. 스탯 환산
- 경로: '스펙' 탭 > 스탯 환산(`#stat:eff`), 시뮬레이터의 '캐릭터 능력치 > 효율'
- 모드: '전투력'(게임 전투력 공식, 실제 보스 딜과 다르다고 명시) / '예상딜'(10분 기준, 직업 공통 모델 베타)
- 입력:
  - 넣어 볼 스탯 7종(물리 공격력, 물공%, 보공, 물댐, 치피, 최종, 최대 대미지)과 양(%p 또는 수치). 여러 줄로 더할 수 있다.
  - 방무 계산: 보스 선택(24종 + 없음), 장비 방무 옵션을 줄마다 '지금 → 바꾼 뒤'로 입력(새 옵션은 '지금'을 비움)
- 출력:
  - 오르는 전투력(절대값과 %)
  - 같은 양을 다른 스탯으로 올리려면 얼마가 필요한지 보여 주는 등가표와 한 칸당 상승 막대. '실전 낮음' 표식은 전투력보다 실제 딜 기여가 작은 스탯에 붙는다.
  - 방무: 내 방무, 어센틱포스(권장 대비), 어센틱포스 효과를 포함한 최대 대미지, 일반 스킬과 오리진 스킬 기준 실제 피해량·적용률
- 관찰 사례(디올, 기준 867,888,292):
  - 최종 +1%p → +1,646,222(+0.19%)
  - 최종 +5%p → +8,231,111(+0.95%). 1%p의 정확히 5배라서 선형이다.
  - 보공 +10%p → +3,669,418(+0.42%)
  - 물리 공격력 +1,000 → +5,528,655(+0.64%)
  - 등가표: 최종 1%p ≈ 물공% 1.35%p ≈ 치피 1.38%p ≈ 물댐 1.91%p ≈ 물공 298 ≈ 보공 4.49%p ≈ 최대 대미지 3,121만
  - 한 칸당 상승: 최종 +165만, 물공% +122만, 치피 +119만, 물댐 +86만, 물공 100당 +55만, 보공 +37만
  - 방무(카링 HARD, 방어율 80%): 내 방무 86.826%, 어센틱포스 750/권장 550, 최대 대미지 3,383,400,000(어센틱포스 효과 105,000,000 포함). 일반 스킬 3,082,954,080(91.1%), 오리진 Lv.30 3,210,169,920(94.9%)
- 필요 API: stat, symbol(어센틱포스), 엔진
- 추가: 보스 방어율 표, 방무 곱연산 규칙(4장), 예상딜 모델
- 난이도 중(엔진 전제) · 우리: 없음 · 우선순위 P0
- 확인 상태: 확인 완료(사례 4건 기록)

#### F24. 배분 추천
- 경로: 시뮬레이터 > 배분 추천(`growth=recommend`)
- 설명: '전투력 기준'과 '예상딜 기준'(보스를 10분 칠 때) 최적 배분안을 두 열로 나란히 보여 준다. 대상은 장비 마스터리 포인트 배분, HEXA 스탯 옵션 조합(레벨은 그대로, 120가지 비교), 링크 스킬, 하이퍼 스탯이다. 유니온 스탯은 조회값이라 바꿀 수 없다고 표시한다. 열마다 '모두 바꿔 보기'와 항목별 되돌리기가 있다.
- 결과(디올):
  - 전투력 기준 모두 적용: +1,955,252(예상딜 −0.06%). HEXA 스탯 +293,715, 링크 +1,674,580
  - 예상딜 기준: 전투력 −12,725,859, 예상딜 +1.16%, 방무 +2.05%p. 마스터리 장비 3개의 포인트를 에디 보공에서 추옵 방무로 옮기고, HEXA 스탯 부가 옵션을 바꾸는 안이다.
- 난이도 상(예상딜 모델 필요) · 우리: 없음 · 우선순위 P2
- 확인 상태: 확인 완료(계산 진행률 표시 후 결과까지 확인)

#### F25. 큐브·불꽃 효율 추천
- 경로: 시뮬레이터 > 큐브·불꽃 효율(`growth=forgeRec`)
- 설명: 추가옵션/잠재/에디 탭에서 사용 아이템(환생의 불꽃 4종, 큐브 레드·블랙·수상한·초이스)을 고르고 '추천 계산'을 누르면 장비별 현재 완성도, 목표까지 평균 사용 개수, 예상 전투력 상승을 효율 순으로 보여 준다. 묶음은 전투력(보스 장비·심장), 방무, 다른 프리셋, 드롭률, 메소, 경험치, 최대 HP로 나뉜다. 이벤트 토글(큐브 등급 상승 확률 2배)과 일정이 붙어 있다.
- 결과(디올):
  - 추가옵션·영원한 환생의 불꽃: 기계 심장(완성도 34.2%, 평균 4.2개, +2,175,228), 반지(79.4%, 28.6개, +1,722,894), 엠블렘(81.5%, 33.7개, +1,534,173), 무기(84.5%, 43.5개, +1,265,073)
  - 잠재·레드 큐브: 기계 심장(0%, 평균 4개, +2,531,530), 반지(95.1%, 9,730.5개, +344,417)
- 필요 API: item-equipment
- 추가: 큐브·불꽃 옵션 확률표와 등급 상승 확률. 공식 API에 없으므로 넥슨 확률 공개 자료를 반영해야 한다. 우리 사이트의 잠재능력 확률표 데이터를 재사용할 수 있다.
- 난이도 상 · 우리: 부분(잠재능력 확률표) · 우선순위 P2
- 확인 상태: 확인 완료

#### F26. 대장간(장비 강화 시뮬레이터)
- 경로: 시뮬레이터 > 장비 > 아이템 상세 > '대장간'
- 설명:
  - 아이템 상세: 장착 시 예상 전투력, 같은 부위 장비, 기대 비용, 옵션별 출처 분해(기본+추옵+스타포스 등), 완성도 점수
  - 대장간 탭 4개: 강화(스타포스·강화권·이노센트) / 추가옵션 / 잠재·에디 / 소울·문장
  - 스타포스: 목표 성, 파괴 시 복원 주문서 자동 사용, 시도 한도, 세이프티·프로텍트 쉴드, 럭키데이 주문서, 이벤트 토글(20성 이상 성공 확률 2배), 목표까지 평균 횟수, 자동 강화
  - 마스터리 레벨과 옵션 줄별 마스터리 포인트 배분 조절
- 필요 API: item-equipment
- 추가: 스타포스 확률·비용, 주문서, 큐브·불꽃 확률 테이블(공식 API 없음)
- 난이도 상 · 우리: 없음 · 우선순위 P3
- 확인 상태: 일부 확인. 화면과 입력 항목만 봤고 시뮬레이션은 돌리지 않았다.

#### F27. 보스 컷(입장 조건·다음 보스)
- 경로: 시뮬레이터 상단의 '입장 가능 n/28' 또는 '보스 컷'(`growth=boss`), 빠른 메뉴의 '보스 컷·기여도'
- 설명: 입장 가능한 보스 수, 지나온 보스, 남은 보스를 보여 준다. 보스마다 입장 레벨·필요 전투력·방무 대비 방어율·어센틱포스(권장 대비)·대미지 적용률·어센트 지분·권장 참여 조건 충족 여부를 정리한다. '다음 컷까지 n 남음'과 진행률(이전 보스 요구치 → 다음 보스 요구치 구간에서의 위치), 보스 HP, 기여도 링크도 있다.
- 결과:
  - 디올: 28/28 입장 가능. 카링 HARD: Lv.280·필요 764,379,000, HP 약 340조, 적용률 일반 91.1%·오리진 94.9%, 권장 참여 조건 1개 부족
  - 캐슬(340,814,773): 25/28. 다음 컷 감시자 칼로스 HARD(Lv.268·필요 351,328,000)까지 10,513,227 남음(76%). 카링 NORMAL(Lv.280·423,330,000)까지 82,515,227, 카링 HARD까지 423,564,227
- 필요 API: 엔진, symbol(어센틱포스), character/basic
- 추가: 보스별 입장 레벨·필요 전투력·권장 포스·HP 테이블(4장)
- 난이도 중 · 우리: 없음 · 우선순위 P1
- 확인 상태: 확인 완료. 기여도 상세 화면은 열지 못했다.

#### F28. 어센트 보스 지분
- 경로: '캐릭터' 탭 > 어센트 보스 지분(`#char:ascent`)
- 설명: 어센트 스킬 한 번(첫 시전 + 추가 시전)으로 보스 페이즈 HP를 몇 % 깎는지 계산한다. 보스·현재 레벨→목표 레벨·버프 아이템 수를 바꿀 수 있다. 출력은 누적·최대·최소·평균 대미지, 타격 횟수, 페이즈별 HP와 1회·3회 지분이다.
- 결과(디올, 야마즈 디크리 Lv.30·퍼뎀 700%, 카링 HARD): 1회 누적 6.09조, 타당 33.83억, 1,800타(3회 5,400). 1페이즈(약 101조) 6.03%/18.09%, 궁기(약 30조) 20.30%/60.90%, 2페이즈(약 121.5조) 5.01%/15.04%, 폭주한 카링(약 36.5조) 16.69%/50.06%
- 가정 표기: 1인, 쉴드 제외, 방어율 80%, 방무 +100%, 보공 +50%
- 필요 API: hexamatrix-skill(어센트 코어), stat
- 추가: 보스 페이즈 HP, 어센트 스킬 계수, 딜 모델(서버 계산)
- 난이도 상 · 우리: 없음 · 우선순위 P3
- 확인 상태: 확인 완료

#### F29. 세리온 효율(스텔라코드)
- 경로: '캐릭터' 탭 > 세리온 효율, 시뮬레이터 > 스텔라코드 > 세리온 효율(`growth=serion`)
- 설명: 컨스텔라 코어와 스타코러스 개방·강화를 세리온 1개당 예상딜 효율 순으로 줄 세운다(10분 예상딜, 공통 모델 베타 표기). '보유 세리온 N개' 입력 플래너가 있다. 스텔라 값이 비어 있으면 0에서 계산했다고 알린다.
- 결과(디올): 1순위는 별의 송곳니 개방(Lv.0→1, 세리온 1개) 예상딜 +2.89%. 다음은 그림자 성문 개방, 그림자 성문 Lv.1→10(54개, +3.29%) 순
- 데이터: 스텔라코드 전체가 공식 API 미제공이다(수동). 개방·강화 비용 테이블이 필요하다.
- 난이도 상 · 우리: 없음 · 우선순위 P3
- 확인 상태: 확인 완료

#### F30. HEXA 조각 효율 + HEXA 스탯 강화 시뮬레이터
- 경로: '캐릭터' 탭 > HEXA(`#char:hexa`), 빠른 메뉴의 'HEXA 조각 효율', 시뮬레이터 > HEXA 매트릭스 > HEXA 스탯(`growth=hexa`)
- 설명:
  - 조각 효율: 솔 에르다 조각 100개당 예상딜 효율이 높은 순으로 코어 레벨업 단계를 줄 세운다(직업 모델 표기, 예: 렌). '보유 조각 N개' 플래너가 있다.
  - HEXA 스탯 시뮬: 메인·부가 스탯 레벨과 강화 확률, 1회 강화와 한 번 취소, 비용, 0레벨 초기화, 이벤트(메인 5레벨 이상 확률 ×1.2), 목표 메인 레벨까지의 기대값(평균 필요량·조각별 도달 확률·중도 초기화 규칙), '스탯 재분배 추천'
- 결과(캐슬): 1순위 마스터리 코어 Lv.1→2(조각 20, 실전딜 +0.11%, 100개당 +0.55%). 솔 야누스 Lv.1→10(1,001개, +1.42%)
- 필요 API: hexamatrix-skill, hexamatrix-stat
- 추가: HEXA 코어·스탯 비용과 확률 테이블, 딜 모델
- 난이도 상(효율)·중(비용·기대값) · 우리: 없음 · 우선순위 P2. 조각 비용 계산만 먼저 넣는다면 P1.
- 확인 상태: 일부 확인. 효율 목록은 확인했고 강화 시뮬은 실행하지 않았다.

#### F31. 축복(빛의 성소) 시뮬레이터
- 경로: '장비' 탭 > 빛의 성소 > 축복 시뮬레이터(`growth=blessing`)
- 설명: 기도 레벨(1~3), 칸 수(Lv.4·9·13에서 개방), 등급(N~L)과 값을 정하고 최고 전투력·최고 예상딜 자동 선택, 기댓값 계산, 시뮬레이션, 현재 기도 경험치(/300)를 다룬다.
- 데이터: 공식 API 미제공(수동). 확률 테이블이 필요하다.
- 난이도 중 · 우리: 없음 · 우선순위 P3
- 확인 상태: 일부 확인(화면만 확인)

#### F32. 펫 성장 계산
- 경로: 시뮬레이터 > 펫
- 설명: 펫 세트 효과, 펫별 레벨 MAX(50), 펫장비 강화, '한 번에 레벨 50·장비 10강', 자석펫 최대치, 오가닉 펫 먹이 필요량(1→30: 301개, 30→50: 429개, 한 마리 MAX까지 약 730개)

- 난이도 하 · 우리: 없음 · 우선순위 P2. 그쪽 건의함에 '펫 먹이 계산기' 요청이 올라와 있어(10/28) 수요가 확인된다.
- 확인 상태: 확인 완료

#### F33. 유니온 부캐 육성 추천
- 경로: 시뮬레이터 > 유니온
- 설명: '어떤 부캐를 키울까'에서 직업군별로 부캐 1명을 200·250레벨로 키웠을 때 공격대원 효과·레벨 총합·유니온 포인트 증가를 계산하고, 전투력에 들어가지 않는 직업을 구분한다. 레벨 총합만 올려 보기(기존 캐릭터 레벨업)도 된다. 계산 가정을 명시한다(새 부캐는 빈 공격대원 자리에 들어간다고 가정 등).
- 필요 API: user/union, user/union-raider
- 추가: 공격대원 효과·등급 테이블
- 난이도 중 · 우리: 없음 · 우선순위 P2
- 확인 상태: 확인 완료

#### F34. 예상 수로 점수 + 밸런스 패치(보정)
- 경로: 시뮬레이터 상단 지표
- 설명:
  - 지하수로 점수를 예상한다(치명타 확률 100% 기준, 공통 모델이면 오차 안내).
  - '밸런스 패치'는 사용자가 같은 도핑으로 실제로 낸 수로 점수를 넣으면 예상과의 차이(%)를 보여 주고 그만큼 숫자를 맞춘다. 예상딜과 추천은 그대로 둔다.
  - 처리방침에 따르면 입력한 점수는 직업별 예측 정확도 개선에 쓰이도록 서버에 저장된다. 사용자 데이터로 모델을 보정하는 루프다.
- 결과: 디올 475,489,212(베타), 성령 488,740,320(에릴 모델), 캐슬 225,044,907(렌 모델)
- 난이도 상 · 우리: 없음(지하수로 랭킹만) · 우선순위 P3
- 확인 상태: 일부 확인. 입력창만 확인했고 점수 제출은 하지 않았다.

### 3.3 랭킹

#### F36. 전투력 랭킹(+ 홈 '오늘의 랭킹')
- 경로: 랭킹 > 전투력(`/?view=rank`), 홈 위젯(전투력/레벨 탭, 상위 3명)
- 설명:
  - 기준: 최근 30일 최고 전투력 순, '9월 30일부터 모은 기록 · 10월 28일 기준'으로 표기. 데이터는 매일 받는 넥슨 랭킹과 사이트 조회 기록을 합친 것이다.
  - 필터: 월드, 직업(직업군 → 직업, 직업별 인원수 표시). 이름 일부로 찾기(`&q=`), 더 보기(11~60위 단위)
  - 표시: 1~3위는 시상대형 카드, 길드명 노출
  - 내 캐릭터를 등록하면 '내 캐릭터 순위'(전체·월드)와 '근처 보기'가 생기고, '최근 본 캐릭터 순위' 영역이 있다.
- 필요 API: 처리방침에 '넥슨 Open API 랭킹(레벨·전투력·유니온·업적, 각 1만 등)'을 매일 받는다고 적혀 있다. 우리 목록에는 전투력 랭킹 엔드포인트가 없으므로 최신 API에 있는지 확인해야 한다. 캐릭터 화면 말풍선 설정에 '무릉도장 랭킹'도 있어 해당 데이터의 출처도 확인 대상이다.
- 난이도 중(일일 스냅샷 + 30일 최대값) · 우리: 부분(레벨·유니온·업적·전장·지하수로·시간의 근원 6종) · 우선순위 P1(API가 있으면 바로)
- 확인 상태: 확인 완료

#### F37. 레벨 랭킹
- 경로: 랭킹 > 레벨(`type=level`)
- 설명: 사이트가 매일 모은 기록(최근 30일, 넥슨 랭킹과 조회)에 있는 캐릭터를 레벨과 경험치% 순으로 보여 준다.
- 필요 API: ranking/level
- 난이도 하 · 우리: 있음 · 우선순위 P3
- 확인 상태: 확인 완료

#### F38. 아이템 랭킹·장비 옵션 검색
- 경로: 랭킹 > 아이템(`type=item`, `&name=<아이템>`)
- 설명:
  - 부위를 고른 뒤 아이템 계열 탭(예: 무기 제네시스·아케인셰이드·앱솔랩스·파프니르)에서 착용자 수가 붙은 아이템 카드를 보고, 아이템을 고르면 '최근 30일 안에 이 아이템을 낀 사람' 목록이 나온다.
  - 정렬: 스타포스 순·최근 확인 순·등수 순
  - 행: 스타포스, 잠재·추옵 요약, 아이템 점수와 상위 %, 마지막 확인 시각
  - '+ 조건'으로 스타포스(25·30·35성 이상)와 잠재·에디·추옵 줄별 옵션(줄 순서대로/아무 줄이나)을 필터한다.
  - 행을 누르면 아이템 상세(예: '아케인 무기 16,072개 중 167등 · 상위 2%')와 캐릭터 보기로 이어진다.
  - 검색 가능 장비는 부위별로 고정돼 있다. 가방·창고·거래소는 넥슨이 주지 않아 빠진다고 명시한다.
- 결과: 제네시스 대거 97명, 무기 34종(제네시스)
- 필요 API: item-equipment를 랭킹 캐릭터 1만여 명분 매일 재조회해야 한다(처리방침이 그렇게 밝힘). 호출량이 큰 자체 수집이다.
- 난이도 상(수집량·저장·검색 인덱스) · 우리: 없음 · 우선순위 P2
- 확인 상태: 확인 완료

#### F39. 자유전직 통계
- 경로: 랭킹 > 자유전직(`type=jobchange`)
- 설명:
  - 범위: 전투력·레벨 랭킹 1만 등. 자유전직 기간(10/1~11/11)에 9월 랭킹 인원 중 직업을 바꾼 사람 수(19,079명 중 1,302명)를 집계한다.
  - 표: 직업군과 직업별로 9월 인원·유출·유입·증감(%)을 막대로 보여 주고 정렬할 수 있다. 행을 펼치면 유출·유입 상대 직업 비율이 나온다.
  - 필터: 월드, 기간(자유전직 기간/최근 7일), 전투력 1,000등 안
  - 옆 패널: 날짜별 자유전직 인원 막대(가장 많은 날 10/2, 288명), 내 캐릭터 직업 강조
- 결과: 증가 1위 아크메이지(썬·콜) +157(+23%), 감소 1위 비숍 −275(−20%)
- 필요 API: ranking/level 등의 일일 스냅샷(ocid별 직업 변화 추적)
- 난이도 중 · 우리: 없음(일일 스냅샷 인프라는 있음) · 우선순위 P2(이벤트 기간 한정)

#### F16. 경험치 기록·레벨업 예상일·같은 레벨 비교

  - 하루 경험치: '얻은 경험치'와 '일일 과제 경험치를 뺀 양'을 토글로 보고, 같은 레벨 평균 대비 배수와 같은 레벨 n명 중 상위 %를 보여 준다.

  - 캐슬(Lv.280 38.83%): 하루 +15.72% → 약 4일(11/1). 606조 vs 169조(3.58배), 655명 중 상위 6%. 일일 과제 157조

- 추가: 레벨별 필요 경험치(조 단위 환산), 레벨별 일일 과제 경험치 테이블
- 난이도 하~중 · 우리: 부분(자체 로그 기반 경험치 히스토리) · 우선순위 P0. 예상일·같은 레벨 비교·과제 외 경험치를 더하는 고도화가 저비용으로 체감이 크다.
- 확인 상태: 확인 완료(2명)

#### F35. 해방 일지(해방 예정일 플래너)

  - 해방 예정일과 D-day, 모은 포인트(/13,500)
  - 주별 기록(목요일 기준), '이벤트로 더 잡음', '포인트 맞추기'(게임 값에 보정), 매주 잡는 보스 고치기
  - 챕터별 시작 예정일 타임라인, 처음부터 다시
  - 홈 '내 캐릭터' 카드에 해방 D-day 노출
- 결과(캐슬, 기본값: 어둠의 흔적 0포인트, 매주 215 + 매달 350): 해방 2027-09-02(309일 뒤). 아카이럼 26.11.1 → 매그너스·힐라 26.12.1 → 스우 27.1.1 → 1차 해방·반 레온·데미안 27.2.4 → 루시드 27.4.1 → 윌 27.5.13 → 마지막 흔적 27.7.8 → 2차 해방 27.9.2
- 해방을 끝낸 캐릭터: 제네시스 무기 착용을 감지해 '해방 완료'와 챕터 표를 보여 준다(디올).

- 확인 상태: 확인 완료(진행 중·완료 두 상태 모두)

#### F40. 내 캐릭터
- 경로: 캐릭터 화면 '+ 내 캐릭터로', 홈 '내 캐릭터' 영역, 상단 '내 캐릭터' 메뉴, '관리' 모달
- 설명:

- 필요 API: character/basic 등 조회 데이터. '접속 중' 표시의 출처는 확인이 필요하다(character/basic에 접속·종료 시각 필드가 있는지 등).
- 난이도 하 · 우리: 없음 · 우선순위 P0
- 확인 상태: 확인 완료(로컬 동작)

#### F41. 성장 일지
- 경로: '스펙' 탭 > 성장 일지(`#stat:journal`)
- 설명: 내 캐릭터로 등록한 날부터 매일 보스 프리셋 전투력, 바뀐 장비·성장, 각각의 기여도를 기록한다. 기간은 30일·3개월·1년·전체로 볼 수 있고, 다음 보스까지 남은 전투력과 접속 상태도 나온다. 처리방침상 레벨·경험치·순위·길드도 날짜별로 남긴다. 로그인하면 날짜별로 합쳐 서버에 저장한다.
- 필요 API: 조회 데이터 일별 스냅샷 + 엔진
- 난이도 중 · 우리: 부분(경험치 히스토리) · 우선순위 P1
- 확인 상태: 일부 확인. 등록 첫날 화면만 봤고 여러 날이 쌓인 화면은 보지 못했다.

#### F42. 관심 캐릭터·최근 본 캐릭터

- 설명: 남의 캐릭터를 관심으로 표시하면 홈 목록 맨 위에 모인다. 최근 본 캐릭터는 시간·전투력과 함께 쌓이고 기록을 지울 수 있다. 비교(F18) 대상 선택 탭과도 연결된다.
- 필요 API: 없음(로컬)
- 난이도 하 · 우리: 없음 · 우선순위 P0
- 확인 상태: 확인 완료

#### F43. 카카오 로그인·기기 간 동기화
- 설명(공개 문구 기준): 카카오 로그인만 지원하며 카카오 회원번호 외 정보는 받지 않는다고 한다. 동기화 대상은 빈칸 채우기 값, 내 캐릭터 목록, 성장 시뮬레이터 가방·설정, 성장 일지, 해방 일지, 화면 설정이다. 로그인 전에 기기에 있던 값은 계정에 같은 항목이 없을 때만 올린다. 계정 메뉴에서 저장값을 지우고 탈퇴할 수 있다. 세션 쿠키는 180일이다.
- 난이도 중~상(OAuth·계정 저장소·처리방침) · 우리: 없음 · 우선순위 P2
- 확인 상태: 확인 불가. 로그인은 조사 규칙상 금지라 버튼, 빠른 메뉴 문구, 처리방침으로만 파악했다.

#### F44. 캐릭터 인증
- 설명(공개 문구 기준): 사이트가 지정한 아이템을 지정한 프리셋 칸에 끼우게 한 뒤 넥슨 API로 장비 프리셋을 조회해 소유를 확인한다. 인증하면 조회 화면과 랭킹에서 이름 옆에 인증 표시가 붙는다. 회원이 고른 기록(빈칸 채우기 값·성장 일지·해방 일지)을 다른 사람이 읽기 전용으로 볼 수 있다. 같은 캐릭터를 다른 회원이 인증하면 기존 인증은 해제된다. 2026-10-21에 도입됐다(처리방침 개정).
- 필요 API: item-equipment(프리셋)
- 난이도 중 · 우리: 없음 · 우선순위 P3
- 확인 상태: 확인 불가. 로그인이 필요해 홈 카드의 '인증하기' 진입점, 처리방침, 운영자 답변으로만 파악했다. 조사 중 인증된 캐릭터도 만나지 못했다.

#### F46. 빠른 메뉴·입력 유도 말풍선·캐릭터 표정
- 설명:
  - 캐릭터 화면 구석의 캐릭터(마스코트)를 누르면 빠른 메뉴가 열린다. 메뉴: 빈칸 하나 먼저 넣기, 비교, 내실 리포트, 성장 시뮬레이터, 배분 추천, 큐브·불꽃 효율, 보스 컷·기여도, 스탯 환산, 세리온 효율, 어센트 보스 지분, HEXA 조각 효율, 포토카드·링크 공유, 새로 불러오기, 관심 등록, 다크 모드, 카카오 로그인
  - 말풍선이 '빈칸 n개 남음, 넣으면 전투력이 맞게 나옴'을 계속 안내한다(접기 가능).
- 의미: 기능이 많아 생기는 발견성 문제를 한 메뉴로 보완한다.
- 난이도 하 · 우리: 없음(AI 챗봇은 별개 기능) · 우선순위 P2
- 확인 상태: 확인 완료

#### F19. 포토카드
- 경로: '카드로 저장'(모바일에서는 '카드로 저장·링크 공유'로 합쳐짐)
- 옵션:
  - 모양(사진형/장비창형), 방향(세로/가로)
  - 정보 양(간단/보통/자세히, 항목 직접 고르기 n/10)
  - 캐릭터 표정 7종, 자세 4종, 무기 장착/해제, 사진 범위(윗몸/전신)
  - 배경 5종, 카드 테마(화면 따라/밝게/어둡게), 말풍선
  - 이미지 저장, 링크 복사
- 필요 API: character/basic(이미지), stat 등
- 난이도 중 · 우리: 있음(프로필 카드 공유. 꾸미기 범위는 비교 필요) · 우선순위 P2
- 확인 상태: 일부 확인. 옵션 화면만 봤고 이미지 저장은 실행하지 않았다.

#### F20. 링크 공유
- 설명: 현재 캐릭터 링크를 복사한다. 처리방침과 운영자 답변에 따르면 서버에 짧은 링크(월드·이름·빈칸 채우기 값 포함)와 링크 미리보기 카드 이미지(30일 보관)를 저장한다. 로그인 없이 수동 입력값을 다른 사람에게 보여 주는 경로다.
- 관찰: 버튼을 누르자 '복사됨' 안내가 떴고, 서버 저장 요청이 발생해 조사 규칙대로 차단했다.
- 난이도 중 · 우리: 부분(아이템 공유 이미지·카카오 공유) · 우선순위 P2
- 확인 상태: 일부 확인. 결과 링크 형식은 보지 못했다.

## 5. V매트릭스 규칙 대조

요청 배경: 우리 사이트는 지정한 11개 V코어(쓸만한 컴뱃 오더스·블링크·쓸만한 홀리 심볼·쓸만한 샤프 아이즈·쓸만한 하이퍼 바디·쓸만한 윈드 부스터·로프 커넥트·쓸만한 마녀 모자 자리·쓸만한 홀리 파운틴·쓸만한 어드밴스드 블레스·판테온)마다 공격력%를 `7.6 + (레벨 − 1) × 0.6`(최대 25%)로 더한다. 여기에 고정 기본 효과(컴뱃 오더스 데미지 +9%, 샤프 아이즈 치피 +12%, 윈드 부스터 보공 +12%, 어드밴스드 블레스 공% +12%)를 추가로 더한다.

조사 방법: 디올(듀얼블레이드)과 성령(에릴)의 캐릭터 화면 V매트릭스 탭과 성장 시뮬레이터 V매트릭스 영역을 관찰했다. 시뮬레이터에서 코어 레벨을 한 단계씩 내리며 값을 기록했다. 예상딜 서버 계산 요청은 막고 브라우저 안 계산만 봤다.

1. **입력이나 자동 채움이 있나: 있다.**
   - 성장 시뮬레이터의 V매트릭스 영역은 API 조회값(vmatrix)으로 코어 레벨을 자동으로 채운다. 코어마다 레벨 내리기·올리기·MAX 버튼과 '전부 MAX'가 있다.
   - 영역 상단에 공용 코어 공격력% 합계를 'n/250%, 도달률'로 보여 주고, 변경 후 전투력이 즉시 바뀐다.
   - 필터 '전투력(11개)'은 전투력에 들어가는 코어만 모은다. 디올은 공용 10개와 직업 공용 '레디 투 다이', 성령은 공용 10개와 직업 공용 '바디 오브 스틸'이었다.
   - 캐릭터 화면 V매트릭스 탭은 같은 합계와 코어 목록을 조회 전용으로 보여 준다.
   - 스탯 환산(F22)은 V코어 입력이 따로 없고 일반 '물리 공격력%' 입력만 받는다. 내실 리포트는 '공용 코어'를 채움 영역 하나로 센다.
2. **레벨별 값과 상한: 우리 공식과 정확히 같다.**
   - 관찰값(블링크, Lv.30에서 1씩 내림): Lv.30 25% / 29 24.4% / 25 22% / 20 19% / 15 16% / 10 13% / 5 10% / 2 8.2% / 1 7.6% / 없음 0
   - 레벨당 +0.6%p, Lv.1 = 7.6%, Lv.30 = 25%(MAX)다. 레벨 상한이 30이라서 별도 25% 캡은 따로 관찰되지 않았다.
   - 전투력 변화: 레벨당 +733,884로 일정하고, 없음 → Lv.1은 +9,295,859다(디올).
   - 공격력%가 붙는 코어는 10개다: 블링크, 로프 커넥트, 쓸만한 샤프 아이즈, 쓸만한 홀리 심볼, 쓸만한 컴뱃 오더스, 쓸만한 윈드 부스터, 쓸만한 어드밴스드 블레스, 쓸만한 하이퍼 바디, 쓸만한 홀리 파운틴, 쓸만한 마녀 모자 자리. 10개 모두 Lv.30에서 같은 25%로 표시된다. 직접 Lv.30→없음으로 바꿔 본 블링크·컴뱃 오더스·샤프 아이즈·윈드 부스터·어드밴스드 블레스·홀리 심볼 6개는 결과가 똑같았다(물공% 514%→489%, 전투력 −30,578,483). 10개 × 25% = 250%가 화면 상한이다.
   - '쓸만한'이 붙지 않은 블링크·로프 커넥트도 25%를 받는다. 따라서 "쓸만한 코어만 최대 25%"라는 이해는 그 사이트와 맞지 않는다. 그 사이트는 이 10개 이동·버프 코어에 똑같이 적용한다.
   - 공용 코어 15개 가운데 공격력%가 없는 코어:
     - 에르다 노바, 에르다 샤워, 에르다의 의지: 스탯 효과 표시가 없다. 에르다 샤워와 에르다의 의지는 Lv.0→5로 올려도 전투력이 변하지 않았다(에르다 노바는 이미 Lv.30이라 올려 볼 수 없었다).
     - 스파이더 인 미러, 크레스트 오브 더 솔라: '전투력 밖' 표시, 점수 4,650,000
   - **판테온은 두 캐릭터 모두 목록에 없었다.** 우리 목록에만 있는 코어이므로 실제 게임에서 공용 코어로 존재하는지, API vcore 이름이 무엇인지 확인해야 한다.
   - 직업 공용 코어(우리 목록에 없음): 레디 투 다이와 바디 오브 스틸에 물리 대미지가 붙는다. Lv.1 16.3%, 레벨당 +0.3%p, Lv.30 25%. 관찰값은 Lv.29 24.7%, 25 23.5%, 20 22%, 10 19%. 제거하면 물댐 907.95%→882.95%, 레벨당 전투력 +258,313이다. 같은 직업의 다른 직업 공용 코어(얼티밋 다크 사이트 등)에는 스탯이 없었다.
3. **기본 효과를 넣나: 넣지 않는다(관찰 기준).**
   - 쓸만한 컴뱃 오더스, 샤프 아이즈, 윈드 부스터, 어드밴스드 블레스, 홀리 심볼을 Lv.30에서 '없음'으로 바꿔도 물공%만 25%p 줄었다. 물리 대미지(907.95%), 치명타 피해(609.6%), 보스 공격력(551.86%)은 그대로였다.
   - 어드밴스드 블레스도 25%만 빠지고 +12%는 따로 움직이지 않았다.
   - 그 사이트는 API의 물공%(514%)를 코어 공격력%가 이미 들어 있는 값으로 다루고, 시뮬레이션 때 그 차이만 더하거나 뺀다. 기본 효과가 API 능력치에 이미 들어 있다고 보는지, 아예 무시하는지는 화면으로 구분할 수 없다.
4. **출처나 패치 날짜를 밝히나: 밝히지 않는다.**
   - V매트릭스와 관련해 보이는 설명은 '점수는 전투력 공식 밖'이라는 툴팁과 코어별 게임 설명문이 전부다.
   - 7/9 V매트릭스 개편이나 규칙 버전, 기준일에 대한 언급은 없다. 사이트 전체에서도 계산 규칙의 패치 기준일을 적은 곳을 찾지 못했다. 출처 표기는 캐릭터 데이터가 넥슨 Open API에서 왔다는 것뿐이다.

우리 쪽 시사점:
- 레벨별 공식(7.6 + 0.6×(Lv−1), Lv.30 = 25%)은 그 사이트와 일치한다.
- 차이 ①: 그 사이트는 기본 효과(+9/+12/+12/+12)를 더하지 않는다.
- 차이 ②: 판테온을 다루지 않는다.
- 차이 ③: 직업 공용 코어의 물리 대미지(16.3→25%)를 넣는다.
- 우리 계산이 API 능력치 위에 코어 공격력%와 기본 효과를 더하는 방식이라면 이중 합산 위험이 있다. 인게임 능력치 창 값으로 한 캐릭터를 직접 대조해 검증하기를 권한다.

## 6. 데이터 신선도, 모바일 UX, UX 장단점

### 6.1 데이터 신선도 처리
- 캐릭터 화면:
  - 헤더에 '기준 시각'을 늘 띄우고, 펼치면 정확한 갱신 시각(KST)이 나온다.
  - 툴팁에는 '24시간 이내 저장 데이터 자동 사용'이라고 적혀 있다. 다만 새 브라우저 세션에서 조회할 때마다 기준 시각은 조회 시각으로 갱신됐다. 브라우저 캐시 정책인지 서버 캐시인지는 불분명하다.
  - 새로 불러오기와 조회에는 몇 초 쿨다운 카운트다운이 붙는다.
  - '방금 받은 정보' 같은 상태 표시가 있다.
- 랭킹: 'n월 n일 기준, 매일 모은 기록, 최근 30일 최고, 9월 30일부터 수집'처럼 수집 범위와 기준일을 문장으로 밝힌다. 아이템 랭킹은 '랭킹 캐릭터는 하루 한 번 확인'이라고 적고, 행마다 'n시간 전 확인'을 붙인다. 30일이 지난 기록은 찾지 않는다.
- 추정값 표시: 공통 모델 '베타', 직업 모델이면 직업명, 'API 미제공' 표시, 역산 값(마스터리) 툴팁, 계산 서버 연결 실패 안내가 있다. 다만 계산 규칙의 패치 버전이나 기준일은 표시하지 않는다.
- 운영 이력: 업데이트 내역 페이지는 없다(사용자 요청에 운영자가 준비하겠다고 답한 상태). 처리방침 개정 비교표가 기능 변경을 알 수 있는 유일한 공개 기록이다.

### 6.2 모바일(390×844)과 데스크톱(1440×900) 차이

### 6.3 UX 장점
- 결론이 숫자 하나로 모인다. 전투력 하나와 '빈칸 n개'라는 미완성 표시로 사용자를 다음 행동(입력)으로 이끈다.
- 키울 거리를 바로 보여 준다. 다 채우면 얼마, 다음 보스까지 얼마, 1개당 효율 같은 형태로 거의 모든 화면이 '다음에 무엇을 할지'로 끝난다.
- 정직한 표기가 많다. API 미제공, 역산, 베타 모델, 수집 시작일, 30일 기준을 화면에 적는다.
- 로그인 없이도 거의 모든 기능을 쓸 수 있다. 브라우저 저장을 먼저 쓰고, 로그인은 동기화와 공개 용도로만 쓴다.
- 딥링크가 촘촘하다. 하위 화면까지 해시와 쿼리로 공유할 수 있다.
- 모바일 우선으로 설계했고 PWA를 지원한다.

### 6.4 UX 단점(우리가 파고들 틈)
- 정보 과밀: 49개 기능이 캐릭터 화면 하나와 시뮬레이터 하나에 몰려 있어 빠른 메뉴 없이는 찾기 어렵다. 용어 장벽도 높다(내실, 컷, 지분, 도핑, 막힘).
- 용어가 흔들린다: 같은 지표를 화면에 따라 '예상딜'과 '실전딜'로 부르고, 모델 표기도 '베타'와 직업명이 섞인다.
- 전투력이 혼란스럽다: 계산 전투력, 랭킹 전투력, API 전투력이 크게 다른데 같은 화면에서 차이를 설명하지 않는다. 빈칸을 안 넣은 대다수 사용자는 실제보다 30~40% 낮은 숫자를 보게 된다.
- 계산 규칙의 근거(패치 기준일·공식 출처)와 업데이트 내역이 없다.
- 랭킹 범위가 좁다: 전투력·레벨·아이템·자유전직뿐이고 유니온·업적·지하수로·전장·시간의 근원 랭킹은 없다. 길드 단독 페이지도 없고 챌린저스 월드도 지원하지 않는다.
- 공유 링크와 미리보기 이미지를 서버에 저장한다. 카카오톡 공유 버튼은 보이지 않았다.
- 부캐 추정(같은 유니온)은 사생활 측면에서 논란이 될 수 있다.
- 조회 연타 방지 쿨다운(약 5초)이 체감 속도를 떨어뜨린다.

### 6.5 우리가 더 잘할 수 있는 점
1. 우리가 이미 가진 폭을 살린다: 랭킹 6종 + 전투력 랭킹, 길드 페이지, 챌린저스 월드, 카카오 공유, 잠재능력 확률표.
2. 계산기마다 '적용 패치·기준일·공식 출처·검증 사례'를 붙이고 변경 이력 페이지를 둔다. 그 사이트에 없는 신뢰 장치다.
3. 전투력을 3층으로 투명하게 보여 준다: API 값 / 계산값 / 빈칸을 다 채운 추정값. 차이가 나는 원인도 함께 보여 준다.
4. 우리 서버 로그(경험치 히스토리 등)를 써서 로그인 없이도 과거 추이를 보여 준다. 그 사이트의 성장 일지는 '내 캐릭터로 등록한 날부터'만 기록된다.
5. 빈칸 입력 부담을 줄인다: 항목별 대표값 프리셋, 최근 패치 기본값, 같은 직업 상위권 중앙값 같은 추정 채움.
6. 정보 구조를 단순하게 만든다: 조회(보기) / 계산기(가정) / 내 성장(기록) 3축으로 나누고 용어를 통일한다.
