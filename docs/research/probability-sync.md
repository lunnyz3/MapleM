### 2-4. `_meta`

모든 파일에 같은 필드를 둔다: `source`(공식 URL), `source_title`, `generated_at`, `generator`, `note`. 필요한 파일에만 다음을 더한다.

- `official_keys`: 공식 표 이름을 사이트 키로 나눈 경우(예: '한벌옷, 상하의 170' → 한벌옷 170·상의 170·하의 170)
- `official_notes`: 공식 페이지의 정정·변경·레벨 안내 문구(2-1의 정정 안내, 소수점 변경, 제네시스 무기 안내, '잠재옵션 범위' 안내)
- `level_exceptions`: 부위별 잠재옵션 페이지의 '잠재옵션 범위' 표(3장)

## 3. 레벨 표 선택 예외

`item-share.js`는 아이템 레벨과 가장 가까운 '<부위> <레벨>' 표를 고른다. 공식 페이지는 일부 장비에 다른 레벨의 표를 쓴다고 안내한다. 무기·한벌옷·상의·하의·모자·망토·신발·장갑·어깨·벨트 잠재옵션 페이지에 같은 표가 있고, 보조무기·엠블렘 잠재와 에디셔널 페이지에는 없다(무기 에디셔널 페이지에는 제네시스 안내만 있다).

공식 표에는 세트 이름만 있고 아이템 이름은 없다. 그래서 `item-share.js`의 `TABLE_LEVEL_EXCEPTIONS`에 공식 표 13항목을 모두 옮기되, 아이템 이름으로 세트를 가릴 수 있는 4항목에만 이름 규칙(`namePattern`)을 붙였다. 이름 규칙이 없는 항목은 이전처럼 가장 가까운 레벨 표를 쓴다. 테스트가 이 목록을 `_meta.level_exceptions`와 대조하므로, 공식 표가 바뀌면 재생성 후 `npm test`가 실패해 알려 준다.

## 6. 다시 만들기

```bash
node scripts/data/sync-probability.js --dry-run --changes /tmp/changes.md   # 바뀔 항목만 확인
node scripts/data/sync-probability.js                                       # public/probability/*.json 재생성
node scripts/data/sync-probability.js --verify                              # 공식 페이지와 전 행 대조(불일치면 종료 코드 1)
npm test
```

- 페이지 사이 대기 시간은 기본 1.5초(`--delay`, 최소 1초)다.
- `--snapshot <폴더>`로 읽어 온 원본(표의 행)을 저장하고, `--offline <폴더>`로 네트워크 없이 다시 만들거나 대조할 수 있다.
- 공식 표 내용이 그대로면 파일을 다시 쓰지 않는다(`generated_at`만 바뀌는 변경 없음).
- 페이지 제목이 다르거나, 데이터 행의 칸 수가 7이 아니거나, 모르는 부위 이름이 나오면 아무것도 쓰지 않고 종료 코드 2로 멈춘다. 공식 페이지 구조가 바뀐 경우이므로 원인을 확인한 뒤 스크립트를 고친다.

## 7. 남은 문제

1. 레벨 예외 9항목(3장 '미적용')은 아이템 이름 목록이 있어야 적용할 수 있다. 게임 안 아이템명을 운영자가 확인해 `TABLE_LEVEL_EXCEPTIONS`의 `namePattern`에 넣으면 된다.
2. 루타비스 이름 규칙은 커뮤니티 자료에 기대고 있고, 아가레스 등 5종은 실제 아이템명을 보지 못했다. 운영자 확인이 필요하다.
3. 감시자의 눈(반지)과 모방된 신의 매듭(목걸이)은 공식 엠블렘 표 대상이고 이제 파일에도 들어 있지만, 상위 % 계산 대상 부위는 아니다(`classifyProbabilitySlot`). 넣을지는 운영자가 정한다.
4. 상위 %가 0.0000005% 미만이면 기존 표시 형식(소수 6자리) 때문에 "상위 0.000000%"로 보인다. 이번 변경 전부터 있던 표시 한계다.
5. 모자 180 레전더리 에디셔널 보스 공격력 정정(2-1 셋째 줄)은 공식 정정 안내가 없어 언제 바뀌었는지는 알 수 없다.

## 8. 추가 옵션(환생의 불꽃) 확률표 (2026-10-28 추가)

- 출처: 공식 '확률형 아이템 정보' [환생의 불꽃 - 추가 옵션(5795)](https://m.nexon.com/probability/5795?language=ko). 메이플스토리M 확률 페이지 번호 5780~5830, 6240~6460을 훑어 추가 옵션 페이지는 이것 하나뿐임을 확인했다.
- 파일: 공식 장비 묶음마다 하나. `weapon_flame_prob.json`(무기, 보조무기, 엠블렘, 감시자의 눈, 모방된 신의 매듭), `armor_flame_prob.json`(방어구, 공용 방어구), `accessory_flame_prob.json`(포켓 장비, 장신구), `heart_flame_prob.json`(기계심장, 레벨 대신 '등급' 2·3·5). 사이트는 앞의 둘만 계산에 쓴다.
- 형식: `{ _meta, "<불꽃 이름>": { two_option_chance, level_basis, options: [{ option, p, step, ranges: { "<레벨>": { min, max } } }] } }`. 불꽃 4종(골드리프, 환생의 불꽃(캐시상점), 강력한, 영원한) × 묶음 4개 = 16블록, 옵션 175개. 글자는 공식 표기 그대로다(공식 표의 `10.0000%%` 오타 포함).
- 공식 규칙: 옵션은 1~2줄, 둘째 줄이 생길 확률은 골드리프 5%, 캐시 10%, 강력한 50%, 영원한·검은 100%. 수치는 MIN~MAX 에서 '증가값' 간격으로 균등. 제네시스 무기(해방 퀘스트)는 200레벨 범위.
- 대조: `--verify` 가 블록마다 2개 등장 확률·레벨 기준, 옵션마다 이름·확률·증가값·레벨별 MIN/MAX 를 한 칸씩 비교한다. 2026-10-28 밤 온라인 대조에서 1,047/1,047칸 일치(큐브 90,480행과 합쳐 91,527).
- 어느 불꽃인지: API 의 `item_additional_option_grade` 로 정한다. 픽스처 5명의 장비 71개를 불꽃별 범위와 대조하면 등급 3(283개)은 영원한 범위에만, 등급 2(1개, 청은의 서 <종장> 치명타 확률 1.30%·아이템 드롭률 1.60%)는 강력한 범위에만 들어간다. 등급 1(골드리프/캐시)은 응답이 없어 계산하지 않는다.
- 상위 %(`resolveTopPercentBreakdown().additionalOptionProbability`): 직업에 맞는 옵션 묶음(물리/마법 공격력·대미지, 최종 대미지, 방어율 무시 ↔ 아이템 드롭률·메소·경험치 중 줄이 많은 쪽)에 드는 줄마다 `옵션 확률 × (그 값 이상인 칸 수 / 전체 칸 수)`를 곱하고, 둘째 줄은 2개 등장 확률을 한 번 더 곱한다. 잠재 상위 %(`totalPercent`)에는 섞지 않고 자랑 문구에 ", 추가 옵션 상위 3.2%"로 붙인다.

### 9-3. 줄 나누기

API 는 묶음별 보너스 합계(`potential_option_point` 등)만 준다. `item-share.js` 는 보너스를 줄마다 0~2개로 나누는 경우를 모두 만들고, 뺀 값이 공식 표에 있는(불꽃은 MIN~MAX 안인) 경우만 남긴다. 상승량을 모르는 줄은 검사하지 않고 빼지도 않는다. 하나만 남으면 그것을, 여럿이면 상위 % 가 가장 크게(덜 희귀하게) 나오는 것을 쓰고, 하나도 없으면 빼지 않는다. 보너스 6(줄마다 2)은 언제나 하나로 정해진다.

### 9-5. 프리셋 장비

API 는 착용 중인 목록(`item_equipment`)에만 `mastery_info` 를 주고 `equipment_preset[]` 의 같은 장비는 null 이다. 서버(`src/transform/equipment-mastery.js`)가 부위·이름·스타포스·잠재·에디셔널·추가 옵션이 모두 같은 착용 장비에서 옮긴다. 후보가 여럿이고 값이 다르면 옮기지 않는다. 피카츄 보스 프리셋 2 는 장갑·어깨·신발·무기를 받고, 이름만 같은 다른 한벌옷(최대 HP 세트)과 착용 목록에 없는 모자·망토는 null 로 남는다.

### 9-6. 확인 불가(빼지 않음)

- 잠재·에디셔널의 고정 수치 옵션(최대 HP·MP, 회복력 등)과 레어·에픽 등급
- 영원한 환생의 불꽃의 마법공격력·메소 획득량·물리/마법 대미지·치명타확률·최대 HP 등 9-2 에 없는 옵션
- 골드리프·캐시 환생의 불꽃의 상승량과 `item_additional_option_grade` 1 의 대응(추가 옵션 상위 % 도 계산하지 않음)
- 착용 목록에 없는 프리셋 장비의 마스터리(API 가 주지 않음)
