# 경쟁 사이트 스탯 보정 자료 (maplemworlds.kr · maplemtool.com)

maplem.co.kr 스탯 계산을 보정하려고 두 경쟁 사이트가 **공개 화면에 보여 주는** 스탯 합계, 출처별 내역, 기본값과 규칙 문구를 모았다. 화면에 보이는 게임 수치와 규칙만 기록했다. 그 사이트의 JS 코드, 내부 API 응답, DB는 가져오지 않았다.

## 0. 수집 범위와 방법

- 수집 시각: 2026-10-28 16:17(구조 확인)·16:43(본 수집 시작)~17:47 KST. 각 JSON의 `capturedAt`(UTC), `capturedAtKST`, `dataAsOf`에 사이트별 시각을 따로 적었다.
  - maplemworlds: 캐릭터 상세의 갱신 버튼 툴팁 '마지막 갱신' 시각. 사이트가 캐시해 둔 데이터라 조회 시각보다 이를 수 있다. 수집한 53명 기준 데이터 나이는 0~23.37시간(중앙값 0.85시간)이다. 0시간은 조회 순간 사이트가 새로 받아 온 경우다(25명). 핵심 5명 중 피카츄·버디는 약 19시간 전 데이터였다.
  - maplemtool: 헤더의 '마지막 갱신' 시각. 새 브라우저로 볼 때마다 조회 시각으로 바뀌었다.
- 대상
  - 핵심 5명(full 수집): 유니온 피카츄(아크메이지(썬,콜)), 스카니아 디올(듀얼블레이드), 스카니아 버디(소울마스터), 스카니아 성령(에릴), 스카니아 몬밀(캡틴).
    - 성령: 우리 API 공식 전투력 랭킹(2026-10-27)에서 전체 4위·에릴 1위(1,153,901,361), 월드 스카니아. 요청서의 '1위'는 직업 내 순위로 보고 진행했다.
    - 캡틴: 레벨 랭킹(2026-10-27) 1페이지에서 처음 나온 캡틴인 스카니아 몬밀(전체 136위, Lv.294).
  - 추가 48명(lite 수집): `sample-50.json`의 `picked` 48명(공식 전투력 랭킹 1~10페이지, 직업당 1명).
- 도구: Headless Chromium(Playwright, `scripts/dev/browser.js`), 데스크톱 1440×900, ko-KR, Asia/Seoul.
- 흔적·부하 관리
  - 두 사이트로 가는 GET 이외 요청은 모두 Playwright route로 막았다. 막힌 요청은 아래 3종뿐이다.
    - maplemworlds `POST api.maplemworlds.kr/api/logs/action`: 사이트 행동 로그
    - maplemtool `POST /cdn-cgi/rum`: Cloudflare 방문 분석 비컨
    - maplemtool `POST /api/real-damage`: 예상딜·예상 수로 점수 서버 계산. 막아서 화면에 '모름'으로 나온다. 스탯·전투력 수집에는 필요 없어 허용하지 않았다.
  - 갱신(새로 불러오기)·로그인·제출·공유·카드 저장 버튼은 누르지 않았다. 펼치기, 탭·프리셋 전환, 툴팁처럼 브라우저 안에서만 바뀌는 조작만 했다.
  - 캐릭터 1명당 사이트별 페이지 로드는 1회다. 구조 확인 단계에서 디올을 더 열었고, 몬밀 maplemtool은 게임 현재 조합 전환이 안 돼 한 번 더 열었다(3장 maplemtool 예외). 한 번 로드한 뒤에는 브라우저 안 조작만 했다.
  - 속도 조절 이력
    - 16:43~17:09 KST: 사이트마다 한 번에 1페이지, 같은 사이트 로드 사이 3초 이상(핵심 5명과 노을).
    - 17:09~17:13: 운영자 지시로 최대 7페이지 동시(maplemtool ≤4, maplemworlds ≤3), 작업 시작 간격 0.5초.
    - 17:13~17:47: 이 서버가 운영 중인 maplem.co.kr도 함께 돌리고 있어 로컬 부하(load average 11)를 줄이려고 4페이지(maplemtool ≤3, maplemworlds ≤2)로 낮췄다. 원격 사이트 쪽 신호 때문에 줄인 것은 아니다. 수집 중 maplem.co.kr 응답은 0.7~1.1초로 평소와 같았다.
  - 차단·지연 감시: 페이지마다 문서·API 응답 상태 코드만 확인했다(본문은 저장하지 않음). 403/429, CAPTCHA·차단 문구, 원격 응답 지연(초기 기준의 3배 이상이 2회 연속)이 보이면 1페이지·2초 간격으로 자동으로 돌아가게 했다. 이런 신호는 한 번도 나오지 않아 전환은 일어나지 않았다. 상태 코드를 기록한 96건은 모두 HTTP 200이었다. 감시를 넣기 전에 수집한 10건(핵심 5명 일부와 노을)은 코드 기록이 없지만 화면이 정상으로 열렸다.
  - 운영자 요청 중 "페이지가 스스로 불러오는 JSON 응답 저장"은 권한 정책에서 거부되어 수행하지 않았다. 모든 값은 화면 텍스트(DOM innerText)에서 나왔다.
- full 수집과 lite 수집의 차이
  - 두 수집 모두 들어가는 것: 보스 세팅 상태와 게임 현재 조합 상태의 스탯 합계, 출처별 내역, 전투력, 프리셋 번호, 옵션 요약, 스탯 효율 기본 화면. 사이트별 원문은 maplemworlds 12개 탭, maplemtool 장비 옵션·하이퍼·HEXA·장착 스킬·유니온·링크·길드 화면이다.
  - full에만 있는 것: maplemworlds의 장비 프리셋 1/2/3 단독 변경 상태, 대미지 효율 모드(도핑·보스 기본값), 수동 입력 칩 7종의 기본 화면. maplemtool의 예상딜 모드 화면, 빈칸 채우기 8항목별 화면, 성장 시뮬레이터 15개 영역, 그 밖의 하위 화면 전체.

| `.cache/calibration/competitor/<월드>-<이름>/mw/dom.json`, `mt/dom.json` | 53명 원본 화면 캡처(탭·패널 원문, 버튼 상태, 요청 로그). 스크린샷 `0.png`·`restored.png` |

`.cache/`는 gitignore 대상이다. 수집 스크립트(`mw_capture.js`, `mt_capture.js`, `driver.js`, `build.js`, `analyze.js`)는 작업 폴더 밖 세션 임시 폴더에 두었고 저장소 코드는 고치지 않았다.

### JSON 읽는 법

- `maplemworlds.stats.<라벨>`
  - `total`/`totalNumber`: 보스 세팅(기본 화면) 합계
  - `byToggle`: 상태별 합계. 상태는 `보스 세팅 켬(기본)`, `게임 현재 조합`, full이면 `장비 프리셋 N만 변경`
  - `categories.<분류>.items[]`: `{group, name, value, valueNumber}`. 분류는 장비·스킬·성장·콘텐츠, group은 그 아래 소분류다. 소분류에 항목이 없으면 `groupOnly: true` 1줄로 남겼다.
  - `categoriesByToggle`: 다른 상태의 내역
- `maplemworlds.presets`: 상태별로 쓰인 장비 프리셋·안드로이드 슬롯·하이퍼 페이지·링크/유니온/쥬얼 프리셋과, 계산값 대조로 추정한 HEXA 스탯 페이지
- `maplemtool.stats.<라벨>`
  - `byToggle`: `보스 프리셋(기본)`과 `처음 조회값(보스 끔)`
  - `note`: '표시값은 출처 합산… API 표기 …'처럼 화면에 붙은 주석
- `maplemtool.breakdown.<라벨>.<분류>.sub[]`: 분류(캐릭터·장비·스킬·성장·콘텐츠)를 누르면 뜨는 팝업의 소분류 값. 이름 끝 `▾`(더 펼칠 수 있음)는 `expandable: true`로 바꿨다. `breakdownByToggle`은 보스 끔 상태 내역이다.
- `maplemtool.presets`: 보스 프리셋, 처음 조회 조합(게임 현재), 조합 수, HEXA 스탯 표기, 하위 메뉴의 '사용 중' 표기
- `assumedDefaults`(mt), `manualInputs`·`statEfficiencyDamageMode`(mw): API에 없어서 사이트가 비워 두거나 가정하는 값과 그 기본값
- `rulesSeen`: 화면에서 본 규칙 문구와 규칙성 항목(세트 단계, 레벨 기본 공격력, 패시브 등)을 그대로 옮긴 것

## 2. 두 사이트 규칙 비교

비교 대상: 두 사이트 모두 수집된 53명 중 수동 입력값이 합계에 들어간 5명을 뺀 48명. 뺀 캐릭터: 나로(maplemworlds 인증·서버 저장 입력), 여신(maplemworlds 인증·서버 저장 입력), 메린(maplemtool 공개 입력 '빈칸 ✓'), 토맛토(maplemworlds 인증·서버 저장 입력, maplemtool 공개 입력 '빈칸 ✓'), 쿨럭(maplemtool 공개 입력 '빈칸 7개 남음').

### 2-1. 같은 규칙(값까지 같음)

- 최대 대미지 기본값 4억: maplemworlds '스킬 > 패시브 400,000,000', maplemtool '캐릭터 400,000,000'. 두 사이트 모두 수집된 53명 중 53명에서 확인했다.
- 공통 패시브: 직업과 상관없이 같은 값이다.
  - maplemworlds '스킬 > 패시브'(대미지/보공/치피/최종/최대 대미지): 60%/10%/30%/10%/400,000,000 → 48명
  - maplemtool(대미지/보공/치피): 60%/10%/30% → 48명
  - 직업별 패시브 스킬 차이를 반영하는 흔적은 두 사이트 모두 없었다.
- 해방 무기(제네시스 무기) 최종 대미지 +10%: maplemworlds는 '스킬 > 해방 무기 착용 10%'로 따로 적는다(41명). maplemtool은 '스킬 > 패시브'에 합친다. maplemtool 최종 대미지 패시브 분포: 50%=38명, 40%=5명, 30.5%=1명, 10.5%=1명, 29.5%=1명, 41%=1명, 31%=1명. 값은 패시브 10% + 해방 무기 10%(착용 시) + 솔 야누스(HEXA 공용 코어) 레벨 효과(Lv.30 = 30%)다.
- 세트·스타포스 세트·럭키 아이템: 아케인/칠흑/앱솔/마스터 라벨/펫 세트/소울 세트 값은 같았다(차원 균열의 반지 세트·군단장 전리품 세트·카이/칼로스 소울 제외, 4-4절).
  - 럭키 아이템 규칙은 maplemtool 장비 옵션 화면에만 문장으로 나온다: "제네시스 무기가 럭키 아이템으로 작용해, 이미 3세트 이상인 세트마다 무기 부위를 채운 것처럼 세트 수 +1 과 스타포스가 더해진다".
  - 결과는 두 사이트가 같다(예: 아케인 7세트, '아케인 280성' = 244성 + 무기 36성).
  - 칠흑 세트 단계 표기만 다르다. maplemworlds는 '칠흑 10세트', maplemtool은 '칠흑의 보스 세트 9세트'로 적지만 값은 같다.
- 하이퍼 스탯, 링크, 유니온(스탯·공격대원·레벨 효과), 길드(개인 스킬·어빌리티), HEXA 스탯 합은 분류 이름만 다르고 값은 같다.
  - maplemworlds: '유니온 스탯' + '유니온', '길드' 한 줄
  - maplemtool: '유니온' 하나, '길드 개인 스킬'과 '길드 어빌리티'로 나눔
  - 지하수로·전장 전용 길드 효과는 두 사이트 모두 전투력 스탯에서 뺀다(maplemtool 길드 화면에 '지하수로 전용/전장 전용'으로 따로 표시).
  - 예외(링크): 보스 프리셋 번호가 다른 캐릭터(3장)를 빼고도 링크 값이 다른 캐릭터가 3명 있었다. 수앙(대미지 mw 21.8 / mt 24.3), 폴암(보공 6 / 12), 방패(최종 27 / 30)다. 링크 효과 해석 차이로 보이지만 어느 링크인지는 화면 합계만으로 특정하지 못했다.
- 스탯별 일치 현황은 표 3에 있다. 최대 대미지 47/48, 치명타 피해 40/48, 최종 대미지 43/48, 보스 공격력 37/48, 대미지 37/48가 보스 세팅에서 정확히 일치했다.

### 2-2. 다른 규칙

1. **방어율 무시 곱연산 단위**(가장 중요)
   - maplemworlds: 장비 옵션 **줄마다** 따로 곱한다. 추가옵션 '방무 5.66% + 5.78%'를 두 항으로 곱한다. 내역 화면에는 장비별 합(11.44%)으로 보여 준다. 이 규칙으로 maplemworlds 표시값을 다시 계산하면 47/48명이 소수 셋째 자리까지 일치했다. 예외 1명(하츠, 바이퍼)은 maplemworlds 추가옵션 방무 합이 65.76%로 maplemtool(100.96%)보다 35.2%p 적었다. 같은 보스 프리셋인데 일부 장비의 추가옵션 방무 줄을 maplemworlds가 빼먹은 것으로 보인다(장비명은 화면으로 특정 못 함).
   - maplemworlds는 '아케인셰이드 세트 (합산)' 한 항목으로 '세트 효과 아케인 7세트 (+40%) / 스타포스 아케인 280성 (+16%) = 56%'를 더해 1개 항으로 곱한다. 앱솔은 세트(예: 23%)와 스타포스(9%)를 따로 곱한다.
   - maplemtool: (a) 같은 장비 안의 줄은 더한 뒤 1개 항, (b) 같은 계열 세트+스타포스 세트(앱솔 7세트 + 앱솔 261성)는 더한 뒤 1개 항, (c) 장비 밖 출처(쥬얼·HEXA 스탯 등)는 모두 더한 뒤 1개 항으로 곱한다. 이 규칙(H2)이 47/48명에서 maplemtool 값과 정확히 맞았다. 단순히 maplemworlds 항목을 그대로 곱한 값(H0)은 38/48명만 맞았다.
   - maplemtool 스탯 환산 화면은 "옵션마다 따로 곱해져 3% → 5%는 +2%와 조금 달라요"라고 적는다. 실제 합계는 위처럼 장비 단위로 묶은 값이었다.
2. **공격력% 패시브와 V매트릭스**: maplemtool '스킬 > 패시브' = 50 + 공용 공격 코어 10종(블링크, 로프 커넥트, 쓸만한 샤프 아이즈/홀리 심볼/컴뱃 오더스/윈드 부스터/어드밴스드 블레스/하이퍼 바디/홀리 파운틴/마녀 모자 자리) 공격력% 합(코어당 7.6 + 0.6×(Lv−1), Lv.30 = 25%). 이 식이 48/48명에서 맞았다. maplemworlds는 48/48명 모두 300 고정이었다. 코어가 Lv.30 미만인 캐릭터(몬밀: 쓸만한 홀리 파운틴 1)에서만 값이 갈린다.
3. **레벨 기본 공격력**: 낮은 레벨에서는 같고 레벨이 오를수록 maplemtool이 커진다(Lv.282 차이 +0 → Lv.298 차이 +16, 4-2절 표). 두 사이트 중 어느 표가 게임과 같은지는 확인하지 못했다.
4. **차원 균열의 반지 세트·군단장 전리품 세트**
   - 차원 균열의 반지 세트(1세트, 공격력% 3%): maplemtool은 이 세트가 있는 캐릭터 모두에 넣는다. maplemworlds는 18명에서만 내역에 넣었다. 나머지는 빠져서 공격력%가 3 낮다. 보스 프리셋 번호가 같은 캐릭터에서는 공격력% 차이 +3이 'maplemworlds에 이 줄이 없음'과 정확히 겹쳤다. 표 3의 더 큰 차이(+10~+20)는 보스 프리셋 번호가 달라서 생겼다(3장).
   - 군단장 전리품 세트: maplemtool만 3세트 이상 효과를 넣는다(피카츄 3세트 보공 +4, 몬밀 6세트 보공 +10·최종 +2.5·최대 대미지 +250,000). maplemworlds 내역에는 이 세트 줄이 한 번도 없었다.
5. **소울 세트옵션(공격력)**: maplemworlds는 **위대한 카이** 소울(주력 소울이 카이인 18명 전원)과 **위대한 칼로스** 소울(성령)의 세트옵션 공격력을 넣지 않는다. 비교 대상 48명 중 21명이 여기에 해당한다. maplemtool은 모두 넣는다(카이는 264의 배수 1,056~2,376, 칼로스 2,880 = 288×10). 듄켈·윌·아카이럼 등 다른 소울은 두 사이트 값이 같았다. 소울 세트옵션을 빼고 나면 공격력 차이는 레벨 기본 공격력 차이와 펫 30/소울 게이지 30 교환 정도만 남는다(예외: 하츠 +103, 숑디 −589, 원인 미확인).
6. **출처 분류(귀속)만 다른 것**: 합계는 같고 어느 분류에 넣는지만 다르다.
   - 레벨 기본 공격력: mw 스킬 / mt 캐릭터
   - 최대 대미지 4억: mw 스킬 / mt 캐릭터
   - 솔 야누스: mw 콘텐츠 / mt 스킬
   - 해방 무기: mw 별도 / mt 패시브
   - 기계 심장 잠재·추옵: mw 장비 또는 성장 / mt 성장
   - 펫 30 vs 소울 게이지 30
7. **표시 정밀도**: maplemworlds는 % 값을 소수 둘째 자리, maplemtool은 셋째 자리까지 보여 준다(대미지 860.82 vs 860.825).
8. **전투력**: maplemtool 계산 전투력이 maplemworlds보다 높다(보스 세팅, 중앙값 ×1.0096). 공식 랭킹(10/27) 대비로는 두 사이트 모두 낮다.
   - 공식 ÷ maplemtool 중앙값 ×1.287, 공식 ÷ maplemworlds 중앙값 ×1.295
   - 둘 다 스타코러스·컨스텔라 코어·유니온 챔피언·축복·성흔·명예 배지·몬스터 컬렉션을 0으로 두기 때문으로 보인다. maplemtool은 "넣으면 전투력이 맞게 나와요"라고 안내한다.
   - 근거(수동 입력이 들어간 캐릭터, 공식 대비 비율): 나로 mw 0.981 · mt 0.675, 여신 mw 0.996 · mt 0.719, 메린 mw 0.759 · mt 0.997, 토맛토 mw 1.220 · mt 1.243, 쿨럭 mw 0.766 · mt 0.766. maplemworlds 서버 저장 입력이 있는 나로·여신과 maplemtool 공개 입력이 있는 메린은 그 사이트 값이 공식과 2.5% 안쪽이다. 토맛토는 두 사이트 모두 공식보다 22~24% 높았다(입력값이나 10/27 이후 성장 차이로 보이며 원인 미확인).

## 3. 보스 세팅 규칙(사이트별)

운영 기본값을 보스 세팅으로 정한 데 맞춰, 두 사이트가 보스 세팅에서 어떤 프리셋을 쓰는지 캐릭터마다 기록했다(표 5, 각 JSON의 `presets`).

### maplemtool
- 버튼 툴팁 원문: "프리셋 조합 중 전투력이 가장 높은 조합을 찾아 적용하고, 프리셋 창에서 1~3위를 보여요". 화면 기본값이 이 조합이다.
- 조합 대상은 장비(1~3), 하이퍼 스탯, 링크 스킬, 쥬얼, 기계 심장, 유니온 스탯 프리셋이다. 캐릭터에게 프리셋이 하나뿐인 항목은 프리셋 창에서 빠진다.
  - 프리셋 창은 "조합 N개 중 전투력 순"이라고 표시한다(디올 324 = 3×3×2×3×3×2, 몬밀 9).
  - 1·2·3위 조합의 전투력과 '처음 조회했을 때 조합'(게임 현재 착용)의 전투력을 함께 보여 준다.
- '처음 N' 표기는 보스 조합과 다른 항목에만 붙는다. 같으면 생략된다.
- HEXA 스탯 페이지는 조합 대상이 아니다. 보스 프리셋과 처음 조회 조합에서 스펙 카드의 HEXA 스탯이 같았다(53명 확인).
- 예외: 몬밀은 첫 화면에 1위 조합이 적용돼 있었지만 '보스' 버튼이 눌린 상태로 표시되지 않았고, '처음 조회했을 때 조합' 행도 없었다. 그래서 게임 현재 조합은 프리셋 창의 '처음 N' 번호를 직접 골라 기록했다.

### maplemworlds
- 화면 상단 '보스 세팅' 버튼은 켬/끔 스위치가 아니다.
  - 장비 프리셋(1~3), 안드로이드 슬롯(누를 때마다 다음 슬롯), 그리고 하이퍼(페이지 1~3)·링크·유니온·쥬얼 탭의 프리셋 버튼이 모두 계산값을 바꾼다.
  - 이 선택이 보스 세팅 조합과 모두 같을 때만 버튼이 강조된다. 하나라도 다르게 고르면 강조가 꺼지고, 다시 누르면 보스 세팅 조합으로 돌아간다.
- 보스 세팅 조합을 정하는 규칙 문구는 화면에 없다.
  - maplemtool 1위 조합과 대조하면 46/53명에서 장비·안드로이드(=기계 심장)·하이퍼·링크·유니온·쥬얼 번호가 모두 같았다. 다른 7명은 한 항목만 달랐다: 바니(링크 mw 2 / mt 1), 서연(링크 mw 1 / mt 3), 마술(링크 mw 2 / mt 1), 돼지(유니온 mw 3 / mt 1), 치우천(장비 mw 2 / mt 1), EUdragon(장비 mw 3 / mt 2), 어남동(링크 mw 1 / mt 2).
  - 그래서 maplemworlds도 '자기 전투력 모델 기준 최대 조합'을 고르는 것으로 보인다(추정). 두 사이트의 전투력 계산이 달라 1위 조합이 갈리는 캐릭터가 생긴다.
- HEXA 스탯 페이지: 왼쪽 카드의 페이지 버튼(1/2)은 표시만 바꾸고 계산값은 그대로였다.
  - 내역의 '헥사 스탯' 값과 헥사 탭 페이지별 수치를 대조한 결과, 보스 세팅에서 쓰인 페이지는 페이지 1 20명, 페이지 2 33명였다.
  - 게임 현재 조합으로 바꿔도 같은 페이지였다(53명).
  - 메인 레벨이 더 높은 페이지와는 48/53명만 일치했다. 반면 두 사이트가 같은 페이지를 쓴 경우는 51/51명이었다. '레벨 높은 페이지' 규칙이 아니라, API가 알려 주는 사용 중 페이지를 두 사이트 모두 그대로 쓰는 것으로 보인다(추정, 화면에 API 사용 페이지 표시는 없음).
  - maplemtool 스펙 카드 기준 페이지 분포: 페이지 1 20명, 페이지 2 31명, 판정 불가 2명.

### 게임 현재 조합을 맞춘 방법
- maplemtool은 프리셋 창의 '처음 조회했을 때 조합' 행을 눌렀다. 그 행이 없으면 항목별 '처음 N' 번호를 직접 골랐다. 이 조합의 번호를 maplemworlds에서 그대로 고른 상태를 '게임 현재 조합'으로 기록했다.
- maplemtool '기계 심장 N'은 maplemworlds '안드로이드 슬롯 N'에 대응시켰다(가정). 보스 세팅에서 두 번호를 비교할 수 있는 37명 중 37명이 같았다.

## 5. 기본값·기본 조건

### maplemworlds
- 보스 세팅이 켜진 상태로 열린다.
- 스탯 효율 탭(기본 탭)
  - '전투력' 모드, 기준 스탯 '최종 대미지', 수치 1(%)
  - 결과는 같은 전투력을 내는 다른 스탯의 양과 오르는 전투력이다.
- 대미지 효율 모드
  - 도핑 10종 중 '5종(물공·보공·물댐·치피 +30%)'과 '맥피(물공·치피 +50%)'만 기본 체크('도핑 2')
  - 보스 방어율 기본값은 '하드 감시자 칼로스 (77.89%)'
- 수동 입력 칩 7종(스타코러스, 성흔, 축복, 펫, 유니온 챔피언, 명예 배지, 몬스터 컬렉션)
  - 비인증 캐릭터는 모두 '미입력'(0)이다. 펫만 '입력 완료'로 표시되지만, 펫 레벨 공격력은 0이고 펫 세트(페어리의 가호) 효과만 API에서 들어간다.
  - 입력값은 '내 브라우저 · 로컬 저장'이다. 인증 캐릭터는 소유자가 저장한 값이 모든 방문자에게 적용된다.
- 헥사 스탯 표시 페이지는 1이다(계산과 무관).
- 데이터 신선도: 캐시가 있으면 그 데이터를 보여 준다('n분 전 갱신', 최대 23.37시간 전). 캐시가 없던 캐릭터는 조회 순간 새로 받아 왔다(25명이 0시간, 추정).

### maplemtool
- 보스 프리셋(전투력 최대 조합)이 적용된 상태로 열린다.
- '빈칸 채우기 8개 남음'
  - 스타코러스, 컨스텔라 코어, 유니온 챔피언, 축복, 성흔, 명예 배지, 몬스터 컬렉션, 펫은 API에 없어서 0으로 둔다.
  - 펫만 일부 자동값이 있다('수동 입력이 더하는 전투력 +n만', 디올 +17만·피카츄 +6만·몬밀 +7,481).
  - 화면 안내: "API에 없는 값이라 비워 두면 그만큼 전투력이 낮게 나와요".
- 스탯 환산
  - '전투력' 모드, 넣어 볼 스탯 '최종 대미지 +1%p'
  - 한 칸 = % 스탯 1%p · 공격력 100
  - 보스는 캐릭터별 기본 선택이 다르다(4-5절).
- 예상딜·예상 수로 점수·실전딜: 서버 계산(POST)이라 이번 수집에서는 막혀 '모름'으로 나왔다. 화면에 보인 기본 조건은 '카링 HARD · 버프 아이템 7개', 직업 공통 모델 '베타'.
- 성장 시뮬레이터 기본 기준은 '보스 프리셋'(조회 프리셋 버튼 툴팁: '조회 화면도 보스 프리셋 조합이에요').
- 기타 능력치 주석: "성흔 · 업적(명예 배지) · 몬스터 컬렉션을 제외한 값이에요. (API 미제공)"
- 데이터 신선도: 새 브라우저로 볼 때마다 '마지막 갱신'이 조회 시각으로 바뀌었다.

## 8. 확인하지 못한 것

- 페이지가 스스로 불러오는 JSON 응답 저장(운영자 추가 요청): 권한 정책에서 거부되어 하지 않았다. 모든 수치는 화면 텍스트다. 그래서 두 사이트가 내부적으로 어떤 원본 값을 쓰는지는 보지 못했다.
- maplemtool 예상딜·예상 수로 점수·'최대 대미지에 막히는 비율': 서버 계산 요청(POST /api/real-damage)을 막아 값이 없다.
- maplemtool 출처 팝업에서 '▾'로 더 펼쳐지는 하위 내역은 열지 않았다(패시브▾, 유니온▾, 링크 스킬▾, 잠재옵션▾, 스타포스 강화옵션▾). '스킬 패시브 상세'와 HEXA 스탯 하위 탭도 열지 않았다. HEXA 페이지는 스펙 카드 수치로 추정했다.
- maplemtool 세트별 효과 줄: 화면에 세트 합계만 있어 사냥 장비 조합에서 생기는 치명타 피해 +44%p 차이가 어느 세트에서 오는지 특정하지 못했다.
- maplemworlds 보스 세팅 조합 선택 규칙: 화면에 설명이 없어 maplemtool 1위 조합과의 일치로 추정했다. HEXA 스탯 페이지 선택 규칙도 화면 값 대조로만 추정했다.
- 게임 현재 조합에서 '기계 심장 N = 안드로이드 슬롯 N' 대응은 가정이다.
- 인게임 능력치 창 값: 두 사이트 중 어느 쪽이 게임과 같은지는 이번 수집으로 판단할 수 없다(특히 방어율 무시 곱연산 단위). 인게임 화면 1~2명 대조를 권한다.
- 데이터 시점 차: maplemworlds는 캐시 데이터(최대 23.37시간 전), maplemtool은 조회 시점 데이터다. 그 사이에 장비가 바뀐 캐릭터는 두 사이트 값이 다를 수 있다. 각 JSON의 `dataAsOf`를 같이 보고 판단해야 한다.
- 성령은 요청서에 '공식 전투력 랭킹 1위'로 적혀 있었다. 우리 API 랭킹(10/27)에서는 전체 4위·에릴 1위였고, 이 캐릭터로 진행했다.
